Range Sum Query

Prefix Sum — Range Queries
ArraysPrefix SumRange Query

You are given an integer array A of length N. You are also given a 2D integer array B with dimensions M x 2, where each row denotes a [L, R] query. For each query, you have to find the sum of all elements from L to R indices in A (0-indexed).

Problem Constraints
1 <= N, M <= 10^5
1 <= A[i] <= 10^9
0 <= L <= R < N

sample input
A = [3, 8, 2, 6, 5, 4, 1]
B = [[1, 4], [0, 2], [3, 6]]
sample output
[21, 13, 16]
in plain english

Many queries, each asks 'sum from L to R'. Naively each query takes O(R - L) and the whole thing is O(N * M). Instead, build a prefix-sum array once where prefix[i] = A[0] + A[1] + ... + A[i]. Then any range sum from L to R becomes prefix[R] - prefix[L-1] in O(1). Build cost is O(N), each query O(1), total O(N + M). The only tricky case is L = 0 — there's no prefix[-1], so just return prefix[R] directly.

how to crack it

key insight: Build the running total ONCE; every query is a single subtraction. The L = 0 corner returns prefix[R] directly to avoid prefix[-1].

Brute. Re-scan each slice per query.→Optimal. One pre-pass, every query is O(1).
Brutetime O(N * M) · space O(M)
  1. Allocate result array of length M.
  2. For each query index q from 0 to M-1: read L = B[q][0], R = B[q][1].
  3. Initialise sum = 0; loop i from L to R inclusive; sum += A[i].
  4. Write sum into result[q].
  5. Return result.
★ Optimaltime O(N + M) · space O(N + M)
  1. Allocate long[] prefix of length N. Set prefix[0] = A[0].
  2. Loop i from 1 to N-1: prefix[i] = prefix[i-1] + A[i].
  3. Allocate long[] result of length M.
  4. For each query q: read L, R from B[q].
  5. If L == 0 → result[q] = prefix[R].
  6. Else → result[q] = prefix[R] - prefix[L-1].
  7. Return result.
watch out
  • Sums hit ~1e14 (N=1e5, A[i]=1e9) so use `long`, not `int`.
  • When `L == 0` there is no `prefix[L-1]`; return `prefix[R]` directly.
  • Build the prefix array once before the queries, not per query.
answer — optimal code (java)
public long[] rangeSum(int[] A, int[][] B) {
    int N = A.length;
    long[] prefix = new long[N];
    prefix[0] = A[0];
    for (int i = 1; i < N; i++) {
        prefix[i] = prefix[i - 1] + A[i];
    }

    long[] result = new long[B.length];
    for (int q = 0; q < B.length; q++) {
        int L = B[q][0];
        int R = B[q][1];
        long sum;
        if (L == 0) {
            sum = prefix[R];
        } else {
            sum = prefix[R] - prefix[L - 1];
        }
        result[q] = sum;
    }
    return result;
}

Special Index

Prefix Sum — Odd/Even Split
ArraysPrefix SumParity

Given an array A of size N, find the count of indices such that removing an element from these indices makes the sum of even-indexed and odd-indexed array elements equal.

Problem Constraints
1 <= N <= 10^5
-10^5 <= A[i] <= 10^5
Sum of all elements of A <= 10^9

sample input
A = [4, 3, 2, 7, 6, 1, 6]
sample output
1
in plain english

When you remove index i, the elements to the LEFT keep their original index-parity, but every element to the RIGHT of i shifts down by one — so its parity flips. Build prefixEven[] and prefixOdd[] once. For each i: newEvenSum = (left-half even sum) + (right-half ODD sum, because they shifted). Same for odd. If newEvenSum == newOddSum, count it.

how to crack it

key insight: Pre-compute two prefix sums (one of even-indexed elements, one of odd-indexed). Removing index i flips parity for everything to its right; combine left + flipped-right with subtraction.

Brute. Two nested loops, O(N^2).→Optimal. Two prefix arrays, one final pass.
Brutetime O(N^2) · space O(1)
  1. Initialise count = 0.
  2. For each removal index i from 0 to N-1:
  3. Initialise evenSum = 0, oddSum = 0, idx = 0.
  4. For each j from 0 to N-1, j != i: if (idx % 2 == 0) evenSum += A[j] else oddSum += A[j]; idx++.
  5. If evenSum == oddSum, count++.
  6. Return count.
★ Optimaltime O(N) · space O(N)
  1. Build prefixEven[] where prefixEven[i] = sum of A[k] over k ≤ i with k even (and prefixEven[i] = prefixEven[i-1] when i is odd).
  2. Build prefixOdd[] symmetrically.
  3. Let totalEven = prefixEven[N-1], totalOdd = prefixOdd[N-1].
  4. For each i from 0 to N-1: compute leftEven = (i == 0) ? 0 : prefixEven[i-1]; leftOdd similar.
  5. rightEvenAfterShift = totalOdd - prefixOdd[i] (because right-side odd indices become even after shift).
  6. rightOddAfterShift = totalEven - prefixEven[i].
  7. If leftEven + rightEvenAfterShift equals leftOdd + rightOddAfterShift, count++.
  8. Return count.
watch out
  • Removing index i flips parity of everything to its right — don't forget the shift.
  • At `i == 0` there's no `prefix[i-1]`, so left sums are 0.
  • Use `long` for the sums since total can reach 1e9.
answer — optimal code (java)
public int specialIndex(int[] A) {
    int N = A.length;
    long[] prefixEven = new long[N];
    long[] prefixOdd = new long[N];
    prefixEven[0] = A[0];
    prefixOdd[0] = 0;
    for (int i = 1; i < N; i++) {
        if (i % 2 == 0) {
            prefixEven[i] = prefixEven[i - 1] + A[i];
            prefixOdd[i] = prefixOdd[i - 1];
        } else {
            prefixOdd[i] = prefixOdd[i - 1] + A[i];
            prefixEven[i] = prefixEven[i - 1];
        }
    }

    long totalEven = prefixEven[N - 1];
    long totalOdd = prefixOdd[N - 1];
    int count = 0;
    for (int i = 0; i < N; i++) {
        long leftEven = (i == 0) ? 0 : prefixEven[i - 1];
        long leftOdd = (i == 0) ? 0 : prefixOdd[i - 1];
        long rightEvenAfterShift = totalOdd - prefixOdd[i];
        long rightOddAfterShift = totalEven - prefixEven[i];
        long newEven = leftEven + rightEvenAfterShift;
        long newOdd = leftOdd + rightOddAfterShift;
        if (newEven == newOdd) {
            count++;
        }
    }
    return count;
}

In-place Prefix Sum

Prefix Sum — In-place
ArraysPrefix SumIn-place

Given an array A of N integers. Construct prefix sum of the array in the given array itself.

Problem Constraints
1 <= N <= 10^5
1 <= A[i] <= 10^3

sample input
A = [5, 1, 4, 2, 8, 3]
sample output
[5, 6, 10, 12, 20, 23]
in plain english

Convert A into its own prefix-sum array using O(1) extra space. Walk from left to right starting at i = 1 and add the previous (already-converted) cell into the current one: A[i] = A[i-1] + A[i]. After the loop, A[i] holds the sum of the original A[0..i]. Constraints are small (A[i] ≤ 10^3, N ≤ 10^5) so int is safe — max sum is 10^8.

how to crack it

key insight: Walk i from 1 to N-1 and do A[i] += A[i-1]. The original value at i-1 is already the prefix sum through i-1, so the assignment is safe.

★ Optimaltime O(N) · space O(1) extra
  1. Guard the empty array (return A immediately if length == 0).
  2. Loop i from 1 to N-1.
  3. Set A[i] = A[i-1] + A[i].
  4. Return A.
watch out
  • Start the loop at `i = 1`; `A[0]` stays as-is.
  • Read `A[i-1]` (already updated) then add — don't overwrite before reading.
  • Guard the empty array before touching `A[0]`.
answer — optimal code (java)
public int[] inPlacePrefixSum(int[] A) {
    if (A.length > 0) {
        for (int i = 1; i < A.length; i++) {
            A[i] = A[i - 1] + A[i];
        }
    }
    return A;
}

Equilibrium Index of an Array

Prefix Sum — Equilibrium
ArraysPrefix SumTotal - prefix

You are given an array A of integers of size N. Find the equilibrium index where sum of elements at lower indexes equals sum of elements at higher indexes. If multiple, return the minimum index. If none, return -1.

Problem Constraints
1 <= N <= 10^5
-10^5 <= A[i] <= 10^5

sample input
A = [-7, 1, 5, 2, -4, 3, 0]
sample output
3
in plain english

An equilibrium index has the property: sum of everything strictly LEFT == sum of everything strictly RIGHT. Compute the total sum once. Walk i = 0..N-1 maintaining leftSum (sum of A[0..i-1]). Then rightSum = total - leftSum - A[i]. Return the first i where leftSum equals rightSum. Two corners: i = 0 means leftSum = 0; i = N-1 means rightSum = 0.

how to crack it

key insight: Compute total once. Sweep i once tracking leftSum. rightSum = total - leftSum - A[i]. Stop on the first match.

Brute. O(N^2).→Optimal. Single sweep with running left + algebraic right.
Brutetime O(N^2) · space O(1)
  1. Loop i from 0 to N-1.
  2. Sum A[0..i-1] into leftSum.
  3. Sum A[i+1..N-1] into rightSum.
  4. If they match, return i.
  5. Otherwise continue. Return -1 at the end.
★ Optimaltime O(N) · space O(1)
  1. Compute total = sum of all elements in one pass (use long for safety).
  2. Initialise leftSum = 0.
  3. Loop i from 0 to N-1.
  4. Compute rightSum = total - leftSum - A[i].
  5. If leftSum == rightSum, return i.
  6. Else leftSum += A[i].
  7. If loop finishes with no match, return -1.
watch out
  • Values can be negative, so equal sums may both be negative — compare, don't assume positive.
  • At `i == 0` leftSum is 0; at `i == N-1` rightSum is 0.
  • Return the first match — return early, don't keep scanning.
answer — optimal code (java)
public int equilibriumIndex(int[] A) {
    int N = A.length;
    long total = 0;
    for (int v : A) {
        total += v;
    }
    long leftSum = 0;
    for (int i = 0; i < N; i++) {
        long rightSum = total - leftSum - A[i];
        if (leftSum == rightSum) {
            return i;
        }
        leftSum += A[i];
    }
    return -1;
}

Closest MinMax

Carry-Forward — Latest Positions
ArraysCarry ForwardTwo Positions

Given an array A, find the size of the smallest subarray such that it contains at least one occurrence of the maximum value of the array and at least one occurrence of the minimum value of the array.

Problem Constraints
1 <= |A| <= 2000

sample input
A = [4, 7, 1, 9, 2, 9, 4, 1, 7]
sample output
2
in plain english

Find the global min and global max first (single pass). Walk the array left-to-right tracking lastMin (latest index of a min) and lastMax (latest index of a max). Every time you hit a min or a max, pair it with the OTHER's latest position to form a candidate window and update the best length. The smallest such window is the answer.

how to crack it

key insight: Track the latest position of min and max separately. Every time either updates, the candidate window is |lastMin - lastMax| + 1. Keep the smallest.

Brute. O(N^2).→Optimal. Two running latest-position trackers.
Brutetime O(N^2) · space O(1)
  1. Compute min and max with one pass.
  2. For each l from 0 to N-1, for each r from l to N-1, check if both extremes appear in A[l..r]; if so update best.
  3. Return best.
★ Optimaltime O(N) · space O(1)
  1. Find min and max in one pass.
  2. Initialise lastMin = -1, lastMax = -1, best = N.
  3. Walk i from 0 to N-1.
  4. If A[i] == min: lastMin = i; if lastMax != -1 update best with (lastMin - lastMax + 1).
  5. If A[i] == max: lastMax = i; if lastMin != -1 update best with (lastMax - lastMin + 1).
  6. Edge: if min == max, return 1 (any single index works).
  7. Return best.
watch out
  • If min == max (all equal), answer is 1 — handle it before the sweep.
  • Only pair when the other position exists (`lastMin`/`lastMax` still -1 means skip).
  • Track the LATEST min and max positions, not the first ones.
answer — optimal code (java)
public int closestMinMax(int[] A) {
    int N = A.length;
    int mn = Integer.MAX_VALUE, mx = Integer.MIN_VALUE;
    for (int v : A) {
        if (v < mn) { mn = v; }
        if (v > mx) { mx = v; }
    }
    if (mn == mx) {
        return 1;
    }
    int lastMin = -1, lastMax = -1, best = N;
    for (int i = 0; i < N; i++) {
        if (A[i] == mn) {
            lastMin = i;
            if (lastMax != -1) {
                best = Math.min(best, lastMin - lastMax + 1);
            }
        }
        if (A[i] == mx) {
            lastMax = i;
            if (lastMin != -1) {
                best = Math.min(best, lastMax - lastMin + 1);
            }
        }
    }
    return best;
}

Subarray in Given Range

Indexing — Slice
ArraysIndexing

Given an array A of length N, return the subarray from B to C.

Problem Constraints
1 <= N <= 10^5
1 <= A[i] <= 10^9
0 <= B <= C < N

sample input
A = [5, 8, 3, 9, 2, 1, 7]
B = 2, C = 5
sample output
[3, 9, 2, 1]
in plain english

Copy A[B..C] (inclusive) into a new array of size C - B + 1. One loop, single index translation. Use System.arraycopy in production, but the manual loop makes the index math explicit.

how to crack it

key insight: Allocate a new array of length C - B + 1 and copy A[B..C] into it. Off-by-one is the only hazard.

★ Optimaltime O(C - B) · space O(C - B)
  1. Compute len = C - B + 1.
  2. Allocate int[] result of length len.
  3. Loop i from B to C inclusive; result[i - B] = A[i].
  4. Return result.
watch out
  • Length is `C - B + 1` (inclusive), easy to drop the +1.
  • Write into `result[i - B]`, not `result[i]`.
  • Range is inclusive of C, so loop `i <= C`.
answer — optimal code (java)
public int[] subarrayInRange(int[] A, int B, int C) {
    int len = C - B + 1;
    int[] result = new int[len];
    int idx = 0;
    for (int i = B; i <= C; i++) {
        result[idx] = A[i];
        idx++;
    }
    return result;
}

Generate All SubArrays

Enumeration — Two Nested Loops
ArraysEnumerationSubarrays

You are given an array A of N integers. Return a 2D array consisting of all the subarrays of the array.
Note: The order of the subarrays in the resulting 2D array does not matter.

Problem Constraints
1 <= N <= 100
1 <= A[i] <= 10^5

sample input
A = [4, 7, 2, 5]
sample output
[[4],[4,7],[4,7,2],[4,7,2,5],[7],[7,2],[7,2,5],[2],[2,5],[5]]
in plain english

Enumerate every (start, end) pair with start ≤ end. For each pair, copy A[start..end] into a row of the output 2D array. The total number of subarrays is N*(N+1)/2 — pre-allocate exactly that many rows.

how to crack it

key insight: Two nested loops: start in outer, end in inner. Inner copy fills A[start..end] into a fresh row. Total count = N*(N+1)/2.

★ Optimaltime O(N^3) total output size · space O(N^3) output
  1. Compute total = N*(N+1)/2.
  2. Allocate int[total][] output.
  3. totalIdx = 0.
  4. For start = 0..N-1: for end = start..N-1: allocate int[end-start+1] row; fill by copying A[start..end]; output[totalIdx++] = row.
  5. Return output.
watch out
  • Count is `N*(N+1)/2` — size the output array to exactly that.
  • Inner loop is `end = start..N-1`, so a single-element subarray `[start]` is included.
  • Copy `A[start..end]` into a fresh row each time; don't share the array.
answer — optimal code (java)
public int[][] generateAllSubArrays(int[] A) {
    int N = A.length;
    int total = (N * (N + 1)) / 2;
    int[][] output = new int[total][];
    int idx = 0;
    for (int start = 0; start < N; start++) {
        for (int end = start; end < N; end++) {
            int[] row = new int[end - start + 1];
            int k = 0;
            for (int i = start; i <= end; i++) {
                row[k] = A[i];
                k++;
            }
            output[idx] = row;
            idx++;
        }
    }
    return output;
}

Special Subsequences "AG" - 2

Carry-Forward — Count Pairs
StringsCarry ForwardSubsequence Count

You are given a string A consisting of uppercase English letters. You need to count the number of pairs (i, j) such that A[i] = 'A', A[j] = 'G' and i < j.

Problem Constraints
1 <= length(A) <= 10^5

sample input
A = "BAGAGAAG"
sample output
10
in plain english

Walk left to right keeping a counter aSeen. Whenever you encounter 'A', increment aSeen. Whenever you encounter 'G', add aSeen to the answer (because every previous 'A' pairs with this 'G'). One pass, O(1) extra, O(N) time.

how to crack it

key insight: Single pass keeping count of 'A's seen so far. Each 'G' adds that count to the running pair total.

Brute. O(N^2).→Optimal. Carry-forward count of 'A's.
Brutetime O(N^2) · space O(1)
  1. Initialise count = 0.
  2. Loop i; if A[i]='A', loop j > i counting A[j]='G'; count += that.
  3. Return count.
★ Optimaltime O(N) · space O(1)
  1. Initialise long aSeen = 0 and long pairs = 0.
  2. Loop each char c in A.
  3. If c == 'A': aSeen++.
  4. Else if c == 'G': pairs += aSeen.
  5. Return pairs.
watch out
  • Pairs reach ~2.5e9 for N=1e5 — use `long` or it silently overflows.
  • Add `aSeen` to the answer on 'G', not on 'A'.
  • Only 'A' and 'G' matter; skip every other character.
answer — optimal code (java)
public long agPairs(String s) {
    long aSeen = 0;
    long pairs = 0;
    int N = s.length();
    for (int i = 0; i < N; i++) {
        char c = s.charAt(i);
        if (c == 'A') {
            aSeen++;
        } else if (c == 'G') {
            pairs += aSeen;
        }
    }
    return pairs;
}

Pick from Both Sides!

Rolling Boundary — Two-Pointer Sum
ArraysSliding WindowRolling Boundary

You are given an integer array A of size N. You have to perform B operations. In one operation, you can remove either the leftmost or the rightmost element of A. Return the maximum possible sum of the B removed elements.

Problem Constraints
1 <= N <= 10^5
1 <= B <= N
-10^3 <= A[i] <= 10^3

sample input
A = [-3, 7, 5, -4, 8, 2, -1, 9, 4]
B = 4
sample output
20
in plain english

Start by picking all B elements from the LEFT — that's an initial sum. Then iteratively un-pick the rightmost of those left picks and pick one more from the RIGHT instead. After B+1 configurations (0..B from the right), report the max. The slide is O(B), so total O(B).

how to crack it

key insight: Start with all-from-left. Each step swap one left-pick for one right-pick. Track the max along the way.

★ Optimaltime O(B) · space O(1)
  1. Sum the first B elements into 'sum' and copy to 'best'.
  2. Loop k from 0 to B-1.
  3. sum = sum - A[B-1-k] + A[N-1-k] (un-pick one from the left, pick one from the right).
  4. best = max(best, sum).
  5. Return best.
watch out
  • Values can be negative, so picking more isn't always better — track the max, not the last.
  • Start from all-left and check that config too (best = initial sum before swapping).
  • The swap indexes are `A[B-1-k]` on the left and `A[N-1-k]` on the right — off-by-one bait.
answer — optimal code (java)
public int pickFromBothSides(int[] A, int B) {
    int N = A.length;
    int sum = 0;
    for (int i = 0; i < B; i++) {
        sum += A[i];
    }
    int best = sum;
    for (int k = 0; k < B; k++) {
        sum = sum - A[B - 1 - k] + A[N - 1 - k];
        if (sum > best) {
            best = sum;
        }
    }
    return best;
}

Leaders in an Array

Carry-Forward — Right-to-Left Max
ArraysCarry ForwardRunning Max

Given an integer array A containing N distinct integers, find all the leaders in A. An element is a leader if it is strictly greater than all elements to its right. The rightmost element is always a leader.

Problem Constraints
1 <= N <= 10^5
1 <= A[i] <= 10^8

sample input
A = [12, 5, 18, 3, 9, 7, 2]
sample output
[18, 9, 7, 2]
in plain english

Walk from the right end leftward, tracking the maximum seen so far. The rightmost element is always a leader (nothing is to its right). Each subsequent element is a leader iff it strictly exceeds the running max — and if so, it becomes the new running max.

how to crack it

key insight: Walk right to left tracking maxSoFar. If A[i] > maxSoFar, it's a leader; update maxSoFar.

Brute. O(N^2).→Optimal. One reverse-direction pass.
Brutetime O(N^2) · space O(N)
  1. For each i, scan j > i checking if any A[j] ≥ A[i]; if none, A[i] is a leader.
★ Optimaltime O(N) · space O(N)

META PROBLEM. Not a single Scaler task — a decision tree to pick the right algorithm for ANY subarray problem.

When the input array contains:
• ALL POSITIVES (or all non-negatives) — sums are MONOTONE in window size → SLIDING WINDOW.
• MIXED SIGNS (negatives allowed) — sums are NOT monotone → SLIDING WINDOW BREAKS. Use HashMap (for sum == k) or Merge-sort on prefix sums (for sum ≤ k / ≥ k).
• 'Exactly k distinct' problems → atMost(k) − atMost(k − 1) trick.

Master three algorithms and you cover ~95% of subarray problems:
1) HashMap on prefix sums — handles negatives, equality (= k).
2) Sliding Window (two pointers) — positives only, ≤ / ≥ / fixed.
3) Merge-sort on prefix sums — handles negatives, ≤ / ≥.

Kadane is sliding-window-for-maximum-sum specialised to allow negatives via 'reset when current < 0'.

Problem Constraints

sample input

sample output

in plain english

Every subarray problem reduces to a (constraint, signs) pair:
• (= K, any signs) → HashMap of prefix sums; for each running sum S add count of (S − K) seen, then bump count of S.
• (= K, positives) → HashMap also works; sliding-window-with-atMost trick also works.
• (≤ K or ≥ K, positives) → Sliding window: expand right, shrink left when constraint breaks.

how to crack it

key insight: <strong>Three algorithms cover almost every subarray problem.</strong> Pick by asking two questions: (1) Are negatives allowed? (2) Is the constraint equality, ≤/≥, or fixed window? The decision tree picks the algorithm; the rest is template typing.

Use whenever the constraint is sum == K. Negatives allowed (HashMap doesn't care). Counting needs a count-map; longest needs an earliest-index map.→Use ONLY when negatives prevent sliding window AND the constraint is ≤ / ≥. For = K with negatives, use HashMap (Tool 1).
Tool 1 — HashMap of Prefix Sums (handles negatives, sum == K)time O(N) avg · space O(N)
  1. Initialise Map<Long, Integer> seen = {0L: 1} — sentinel so a prefix of K starting at index 0 counts.
  2. long sum = 0; long count = 0; int longest = 0; Map<Long, Integer> first = new HashMap<>(); first.put(0L, -1);
  3. For i = 0..N−1: sum += A[i].
  4. COUNT (= K): count += seen.getOrDefault(sum − K, 0); seen.merge(sum, 1, Integer::sum).
  5. LONGEST (= K): if first.containsKey(sum − K) → longest = max(longest, i − first.get(sum − K)); first.putIfAbsent(sum, i).
Tool 2 — Sliding Window / Two Pointers (positives only)time O(N) · space O(1)
  1. COUNT sum ≤ K (positives): expand r, shrink l while sum > K. For each r, count += (r − l + 1) — number of valid subarrays ending at r.
  2. LONGEST sum ≤ K (positives): same pattern, track best window size after the shrink step.
  3. COUNT sum == K (positives): atMost(K) − atMost(K − 1). Reuse the COUNT-≤-K template twice.
  4. FIXED window size W: build first window in one pass; slide by adding A[i] and removing A[i − W]; emit per slide.
  5. AT-MOST K distinct: maintain HashMap<value, count>; expand r adding A[r]; while map.size() > K, shrink l. count += (r − l + 1).
  6. EXACTLY K distinct = atMost(K) − atMost(K − 1).

  3. Run merge sort on P; during the merge step, for each P[j] in the right half, count P[i] in the left half satisfying the bound (two-pointer scan since both halves are sorted).

  5. For sum = K with negatives: prefer HashMap (Tool 1) — it's O(N) and simpler.
watch out

  • For sum == K with negatives use a HashMap of prefix sums, not two pointers.
  • 'Exactly K distinct' = atMost(K) - atMost(K-1); don't try to count it directly.

    long[] P = new long[N + 1];
    for (int i = 0; i < N; i++) {
        P[i + 1] = P[i] + A[i];
    }
    return mergeCount(P, 0, N, K, new long[N + 1]);

private long mergeCount(long[] P, int lo, int hi, long K, long[] buf) {
    if (hi - lo <= 1) {
        return 0;
    }
    int mid = lo + (hi - lo) / 2;
    long count = mergeCount(P, lo, mid, K, buf) + mergeCount(P, mid, hi, K, buf);
    // count pairs (i, j) with lo <= i < mid <= j < hi and P[j] - P[i] <= K
    int j = mid;
    int valid = mid;
    for (int i = lo; i < mid; i++) {
        while (valid < hi && P[valid] - P[i] <= K) {
            valid++;
        }
        count += (valid - mid);
    }
    // standard merge into buf and copy back
    int p = lo;
    int q = mid;
    int k = lo;
    while (p < mid && q < hi) {
        if (P[p] <= P[q]) {
            buf[k++] = P[p++];
        } else {
            buf[k++] = P[q++];
        }
    }
    while (p < mid) {
        buf[k++] = P[p++];
    }
    while (q < hi) {
        buf[k++] = P[q++];
    }
    for (int t = lo; t < hi; t++) {
        P[t] = buf[t];
    }
    return count;
}

1 ≤ A[i] ≤ 10^9
1 ≤ B ≤ 10^9

sample input
A = [1, 2, 3, 4, 5], B = 5
sample output
[2, 3]
in plain english

Brute O(N²) over subarrays. Optimal (positives only): two pointers l, r; expand r adding to sum; while sum > B shrink from l; if sum == B → return A[l..r]. For first occurrence: take the smallest l that hits sum == B.

how to crack it

key insight: All positive ⇒ shrink window when sum exceeds B (two pointers, O(N)). Alternative: prefix-sum + HashMap (works for negatives too).

Acceptable for small N; not for N=1e5.→Optimal for positive arrays. Use long for the sum to avoid overflow.
Brute — All Subarraystime O(N²) · space O(1)
  1. For l: s = 0; for r ≥ l: s += A[r]; if s == B → return A[l..r]; if s > B → break (positives).
  2. Return [-1].
★ Optimal — Two Pointers (positives only)time O(N) · space O(1)
  1. l = 0; long sum = 0.
  2. For r = 0..N−1: sum += A[r]; while (sum > B && l <= r) sum −= A[l++].
  3. If sum == B → return A[l..r]; else continue.
  4. Return [-1].
watch out
  • Two pointers only work because all values are positive; negatives would break the shrink logic.
  • Return `[-1]` (single element) when nothing matches, not an empty array.
  • Use `long` for the running sum, and return the FIRST match (smallest start index).
answer — optimal code (java)
public int[] solve(int[] A, int B) {
    int l = 0;
    long sum = 0;
    for (int r = 0; r < A.length; r++) {
        sum += A[r];
        while (sum > B && l <= r) {
            sum -= A[l];
            l++;
        }
        if (sum == B) {
            int[] res = new int[r - l + 1];
            for (int k = l; k <= r; k++) {
                res[k - l] = A[k];
            }
            return res;
        }
    }
    return new int[]{-1};
}
