d21 — Binary Search on Array
MethodTimeSpace
searchForStartAndEndIndexOfAnElementInAnArrayO(log N)O(1)
positionWhereTargetIsPresentOrShouldBeInsertedO(log N)O(1)
singleElementInASortedArrayO(log N)O(1)
peakElementO(log N)O(1)
maximumHeightOfAStaircaseO(√N)O(1)
minimumCostToBuildAnArrayO(A × B × log B)O(1)
Why O(log N) — binary search

Each step cuts the remaining candidates in half. Start with N positions → after one comparison N/2 remain → after two N/4. It takes at most log₂(N) comparisons before one candidate remains. No extra storage is allocated, so space stays O(1).

Why O(√N) — maximum height staircase

You add stairs one at a time: stair 1 costs 1 block, stair 2 costs 2, and so on. You stop when blocks run out. The sum 1+2+…+k = k×(k+1)/2. Setting that equal to N gives k ≈ √(2N), so the loop runs about √N iterations.

Why O(A × B × log B) — minimum cost to build array

Sort phase: each of the A rows has B elements. One sort costs B×logB. All rows together: A×B×logB.

Search phase: for each of the A−1 consecutive row pairs, walk B elements in the upper row and run a binary search (logB) on the lower row. That is (A−1)×B×logB.

Both phases are the same order — total O(A×B×logB). Sorting is in-place so space is O(1).

d22 — More Binary Search
MethodTimeSpace
squareRootOfANumberO(log N)O(1)
rotatedSortedArraySearchO(log N)O(1)
findMatrixMedianO(N × log M × log(max))O(1)
addOrNotO(N log N)O(N)
athMagicalNumberO(log(A × min(B,C)))O(1)
BthSmallestTripletSumO(N² × log(max_sum))O(1)
Why O(log N) — rotated array

Even though the array is rotated, at every step one half of the remaining range is fully sorted. You can check in O(1) whether the target is in that half. If yes, search there; if no, search the other half. The range still halves every step.

Why O(N × log M × log(max)) — findMatrixMedian

Binary search runs on the answer space [0, 10⁹] — that is log(max) outer iterations. For each candidate mid, you count how many elements in the matrix are ≤ mid: for each of the N rows you do a binary search over M elements — O(N × log M) per check. Total: O(N × log M × log(max)).

Why O(N log N) — addOrNot

Sort the array once — O(N log N). Then for each of the N elements (as a candidate target), binary search over at most i preceding elements to find the best window count — O(log N) per element, O(N log N) total. Build the prefix sum in O(N). Overall O(N log N).

Why O(log(A × min(B,C))) — athMagicalNumber

Binary search on the answer space [2, A × min(B,C)]. At each mid, count magical numbers ≤ mid with the formula: mid/B + mid/C − mid/lcm(B,C) — O(1) per check. The range is A × min(B,C) wide so the search takes log(A × min(B,C)) steps.

Why O(N² × log(max_sum)) — BthSmallestTripletSum

Binary search on the answer space [0, sum of three largest] — log(max_sum) outer iterations. For each candidate mid, the check function counts all triplets with sum < mid using two-pointer on sorted pairs: the outer loop is O(N), the inner two-pointer is O(N) per element — O(N²) total per check. Total: O(N² × log(max_sum)).

d23 — Binary Search on Answer Space
MethodTimeSpace
paintersPartitionMinimumTimeToPaintO(N log(sum))O(1)
aggressiveCowsLargestMinDistanceO(N log(max−min))O(1)
minimumDifferenceBetweenBooksAllottedO(N log(sum))O(1)
maxSubArrayFactorLessThanBO(N log N)O(1)
Why O(N log(sum)) — painters partition & book allocation

Binary search runs on the answer space [maxElement, totalSum] — that is log(sum) outer iterations. For each candidate mid, the greedy feasibility check walks all N elements once — O(N). Total: O(N log(sum)). No auxiliary storage is needed so space is O(1).

Why O(N log(max−min)) — aggressive cows

Binary search runs on the distance space [1, A[last]−A[first]] — width is (max−min), so log(max−min) iterations. For each candidate distance, the greedy cow-placement check walks all N stalls once — O(N). Total: O(N log(max−min)).

Why O(N log N) — maxSubArrayFactorLessThanB

Binary search on the answer space [0, N] — O(log N) outer iterations. For each candidate length K, the sliding window check scans all N elements once — O(N). Total: O(N log N). The check uses a fixed-size window so no extra storage is needed.

d24–25 — Linked Lists
OperationTimeSpace
traversal / insert / deleteO(N)O(1)
Why O(N)

No index exists. To reach position k you follow k next-pointers from the head. In the worst case that is the last node — N steps. The relinking itself is O(1), but the walk dominates.

d26 — Stacks Basics
OperationTimeSpace
all stack-based methodsO(N)O(N)
Why O(N) time and O(N) space

Every element enters the stack at most once and leaves at most once — two events per element across N elements = O(N) work. The stack can hold all N elements at once in the worst case (e.g. all open brackets with no closes yet), so space is O(N).

d27 — Monotonic Stack
OperationTimeSpace
all monotonic stack methodsO(N)O(N)
Why O(N) despite the inner pop loop

Each element is pushed exactly once and popped at most once. The total number of pops across the entire pass is bounded by N — you cannot pop more than you pushed. Even with a nested while loop, total work is O(N), not O(N²).

d28 — Queues
OperationTimeSpace
sliding window max / first uniqueO(N)O(K)
Why O(N) time and O(K) space

Each index is added to the deque once and removed once — no element is processed more than twice across the whole array. Space is O(K) where K is the window size, because the deque never holds more than K indices at a time.

d29–31 — Trees and BST
OperationTimeSpace
full tree traversal (DFS / BFS)O(N)O(H) DFS · O(W) BFS
BST search / validate / insertO(H)O(H)
sorted array → balanced BSTO(N)O(N)
Why O(N) — tree traversal

Every node is visited exactly once. DFS call-stack depth = tree height H. BFS queue width = widest level W. Both are O(N) in the worst case (degenerate tree).

Why O(H) — BST operations

At each node you make one binary decision — go left or go right — and descend one level. You touch one node per level, so cost = H levels. Balanced BST: H = O(logN). Degenerate (sorted input, no rebalancing): H = O(N).
