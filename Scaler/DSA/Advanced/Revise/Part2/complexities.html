d23 — Binary Search on Answer Space
MethodTimeSpaceWhy
paintersPartitionMinimumTimeToPaint O(N log sum) O(1) Search range [maxBoard, totalSum] = log(sum) steps; greedy feasibility check = O(N) per step
aggressiveCowsLargestMinDistance O(N log(max−min)) O(1) Search range [1, stalls[last]−stalls[0]] = log(max−min) steps; greedy placement = O(N) per step
minimumDifferenceBetweenBooksAllotted O(N log sum) O(1) Same structure as painters; search [maxBook, totalPages]; O(N) greedy check per step
maxSubArrayFactorLessThanB O(N log N) O(1) Search range [0, N] = log N steps; sliding window feasibility check = O(N) per step
Why all answer-space searches are O(N · log range)

The outer binary search runs log(range) times. At each step a greedy scan touches every element once — O(N). Total = O(N log range). The range varies: sum of elements for partition problems, positional spread for cows, N itself for the window problem.

d26 — Stacks: Basic Problems
MethodTimeSpaceWhy
postFixExpression O(N) O(N) Each token processed once; stack holds operands (at most N/2)
balancedParenthesis O(N) O(N) Each character pushed at most once; worst case all opening brackets
doubleCharacterTrouble O(N) O(N) Each char pushed and popped at most once; result built in O(N)
passingGameOfBall O(A) O(A) A passes processed linearly; stack depth = forward-pass chain length ≤ A
redundantBracesUnecessaryBraces O(N) O(N) Push all, pop to matching ( on each ); flag operator inside pop loop
minAddToMakeParanthesisValid O(N) O(N) Single pass; unmatched brackets remain on stack — size = answer
Why all stack methods are O(N) time and O(N) space

Every element enters the stack at most once and leaves at most once — two events per element = O(N) total work regardless of any inner pop loop. Space is O(N) because the worst case (all opening brackets, no closing) fills the stack with every element.

d27 — Monotonic Stack
MethodTimeSpaceWhy
largestRectangleInAHistogram O(N) O(N) Each bar pushed once, popped once; inner while pops are amortized O(1) per element
identifyMaximumMinusMinimumInAllPossibleSubArrays O(N) O(N) Two monotonic stack passes (NSL + NSR); O(N) each; contribution formula is O(1) per element
nextGreaterValues / prevSmallerValuesInAnArray O(N) O(N) Single pass; each element pushed and popped at most once across the entire pass
nextGreaterElementForSubsetQueriesInADistinctArrays O(N+M) O(N) Build NGE map for array2 in O(N); answer each of M queries via hashmap lookup O(1)
Why O(N) despite the inner pop loop

Each element is pushed exactly once and popped at most once. Total push + pop events = 2N. Even with a while inside a for, the combined pop count across the entire execution is bounded by N — you cannot pop what you haven't pushed. This is the standard amortized argument for monotonic stacks.
