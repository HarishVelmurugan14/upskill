Binary Search on a Sorted Array d21, d22 ▼
Signals in the question

The array is sorted, or sorting is implied. You are looking for a position, boundary, or specific value — not all elements. Brute force would scan the whole array but the problem hints at O(logN). The key test: for any candidate mid, can you say "the answer is to my left" or "to my right" in O(1)?

Standard solution skeleton

Set low = 0, high = N-1. Each step: mid = low + (high - low) / 2. Compare element at mid to your target. Too small → low = mid + 1. Too large → high = mid - 1. Exact match → return, or save and keep searching for first/last occurrence. Loop until low > high.

For lower_bound (first index ≥ value): when a[mid] >= target save mid and move high = mid - 1. When a[mid] < target move low = mid + 1. Return saved value at end.

Binary Search on Answer Space d23 ▼
Signals in the question

The answer is a single number (time, cost, distance) and you know its minimum and maximum possible value. The question is phrased as "minimize the maximum" or "maximize the minimum." You can write a check function that, given a candidate answer, tells you in O(N) whether it is achievable.

Standard solution skeleton

Set low = smallest possible answer, high = largest possible answer. Binary search this range. At each mid, run the feasibility check. If mid works, record it and try to do better by tightening the boundary. If it doesn't work, move the other boundary. Return the last value that passed.

Linked List d24, d25 ▼
Signals in the question

The input is a chain of nodes connected by pointers. You need to insert, delete, or rearrange without needing random access by index. Modifying the head is possible, which means the caller needs a new head back.

Standard solution skeleton

Use a dummy node before the real head to eliminate head-deletion special cases. Walk with a prev and curr pointer. To delete curr: prev.next = curr.next. To insert newNode before curr: newNode.next = curr, then prev.next = newNode. Always save curr.next before relinking. Return dummy.next as the new head.

Stack — Matching, Evaluation, Cancellation d26 ▼
Signals in the question

Pairs that must open and close in the right order (brackets, braces). An expression to evaluate where operands come before operators (postfix). Adjacent elements that cancel each other. You need the most recent unprocessed item — which is exactly what a stack gives you.

Standard solution skeleton

Walk the input left to right. On an opening item or value, push. On a closing item or operator, pop and process the pair. After the full pass, an empty stack means everything matched. Always check isEmpty() before popping. For expression evaluation: pop two operands, apply the operator, push the result back.

Monotonic Stack — Nearest Smaller / Greater d27 ▼
Signals in the question

"For each element, find the nearest element to its left/right that is smaller/greater." Rectangle areas or contributions that depend on left/right boundaries. The answer for each element depends on the first element that breaks a sorted order around it.

Standard solution skeleton

Walk left to right. Maintain a stack of indices (not values). Before pushing index i, pop all indices from the top whose values violate the order you want. Each popped index has just found its answer — the current element i is the nearest that broke the order. Push i. Anything still in the stack at the end has no answer on that side (use 0, -1, or N). Store indices so you can compute distances.

Queue / Deque d28 ▼
Signals in the question

A fixed-size window slides across an array and you need the max or min at each position. Elements expire after a fixed number of steps. You need to know which element arrived first among the currently active ones.

Standard solution skeleton

Use a deque of indices in decreasing order of their values. For each new index i: remove all indices from the back whose values are smaller than current (they are useless — current is better and lasts longer). Then remove the front if its index is outside the current window. The front is always the current window's maximum.

Tree Recursion / DFS d29, d30 ▼
Signals in the question

The problem can be expressed as: compute something for a node using results from its left and right children. Path problems, subtree sums, structural checks (balanced, symmetric). The same logic applies at every level.

Standard solution skeleton

Base case first: if the node is null, return a neutral value (0 for sums, true for validations, empty list for collections). Recursive case: call the same function on left and right children, get their results, combine with the current node's contribution, return the combined result. Carry all state upward through return values — avoid global variables.

BST d31 ▼
Signals in the question

The tree has an ordering constraint — left subtree < root < right subtree. You need to search, validate ordering, or build a balanced structure from sorted data. BST properties let you eliminate half the tree at each step, similar to binary search.

Standard solution skeleton

Search: compare target with node.val, go left if smaller, go right if larger. Validate: pass min and max bounds down the recursion — a node is valid only if min < node.val < max. Use long bounds to safely handle Integer.MIN/MAX_VALUE. Build from sorted array: always pick the middle index as root, recurse on the left half for the left subtree and the right half for the right subtree — this keeps the tree balanced.
