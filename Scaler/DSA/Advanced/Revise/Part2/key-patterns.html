Binary Search on a Sorted Array d21, d22 ▼
Signals

Array is sorted. Find a position, boundary, target, or a value that could be inserted. Brute O(N) is possible but hint says O(log N). Key test: for any mid, can you discard one half in O(1)?

Standard skeleton
low = 0; high = N - 1; ans = -1;
while (low <= high) {
    mid = low + (high - low) / 2;
    if (a[mid] == target)  { ans = mid; break; }     // or: save + keep going
    else if (a[mid] < target) low  = mid + 1;
    else                      high = mid - 1;
}
Variants and their twists

First/last occurrence: on match, save mid and keep going. For first: high = mid - 1. For last: low = mid + 1. Never return on first match.

lower_bound (first index ≥ value): save mid when a[mid] >= target and move high = mid - 1. At end, check both lb and lb - 1 for the closest absolute value.

Peak element: if a[mid] < a[mid+1], peak is to the right — move low = mid + 1. Otherwise peak is at mid or left — move high = mid - 1, record mid as candidate.

Single element in sorted array: all pairs break pattern at the single. Even index: pair is (i, i+1). If a[mid] == a[mid+1], single is to the right — low = mid + 2. If a[mid] == a[mid-1], single is to the left — high = mid - 2. Force mid to be even: adjust if mid is odd.

Rotated sorted array: first determine which half is fully sorted (a[low] <= a[mid] → left is sorted). Check if target is inside that sorted half. If yes, narrow there. If no, search the other half.

Matrix median (value-space BS): search space is [min element, max element]. For each candidate mid, count elements ≤ mid across all rows using binary search per row. Answer is the first candidate where count > N×M/2.

Binary Search on Answer Space d23 ▼
Signals

"Minimize the maximum" or "maximize the minimum." The answer is a single number (time, cost, distance, length). You can write a yes/no feasibility check for any candidate in O(N). Direct formula doesn't exist — but you can binary search the answer range.

3 questions to ask before coding

1. What is the search range? — low = smallest possibly valid answer, high = worst-case valid answer.
2. What does the feasibility check test? — "Given this candidate, can I satisfy all constraints with the resources allowed?"
3. Which direction do I keep when check passes? — Minimize-max: go left (try smaller). Maximize-min: go right (try larger).

Standard skeleton
low = min_valid;  high = max_valid;  ans = high;   // or ans = -1 for maximize-min
while (low <= high) {
    mid = low + (high - low) / 2;
    if (feasible(mid)) {
        ans  = mid;
        high = mid - 1;   // minimize-max: try smaller
        // OR: ans = mid; low = mid + 1;  // maximize-min: try larger
    } else {
        low = mid + 1;    // minimize-max: mid too small → go right
        // OR: high = mid - 1;            // maximize-min: mid too large → go left
    }
}
return ans;
Feasibility check skeleton (greedy left-to-right)
boolean feasible(int[] items, int workers, long mid) {
    int used = 1;
    long current = 0;
    for (int x : items) {
        if (current + x > mid) {
            used++;          // start new worker
            current = x;
            if (used > workers) return false;   // early exit INSIDE loop
        } else {
            current += x;
        }
    }
    return true;
}
Per-problem search ranges

Painters partition / Book allocation: low = max(single element), high = totalSum. Use long for low/high/mid/currentSum.
Aggressive cows (maximize min-gap): low = 1, high = stalls[last] − stalls[first] (after sort). Feasibility: place next cow only when gap ≥ mid; return true inside loop when all K placed.
maxSubArrayFactor (longest valid window): low = 0, high = N. Feasibility: sliding window of size mid; return false the moment any window sum > B. On true: ans = mid, go right.

Linked List — Dummy Node, Reverse, Delete d24, d25 ▼
Dummy node — when and why

Use a dummy whenever the head can change (insert at head, delete head, reverse). dummy.next = head makes head-ops identical to mid-list-ops. Return dummy.next as the new head. Never special-case head deletion.

3-pointer reverse (reverseALinkedListInPlaceInOneIteration)
prev = null;  curr = head;  next = null;
while (curr != null) {
    next      = curr.next;   // 1. save forward link FIRST
    curr.next = prev;        // 2. flip pointer backward
    prev      = curr;        // 3. advance prev
    curr      = next;        // 4. advance curr
}
return prev;   // new head

Memory hook: save → flip → slide prev → slide curr. When the loop ends, prev is the new head and curr is null.

reverseBetween — 4-step process

Reverse only nodes at 1-indexed positions B through C.

// Step 1: create dummy, walk to node just BEFORE B
dummy.next = head;
prevNode = dummy;
for (i = 1; i < B; i++) prevNode = prevNode.next;

// Step 2: standard 3-pointer reverse for (C - B + 1) nodes
curr = prevNode.next;   // node at B
prev = null;
for (i = 0; i <= C - B; i++) {
    next = curr.next;
    curr.next = prev;
    prev = curr;
    curr = next;
}
// After loop: prev = node at C (new head), curr = node after C (tail's next)

// Step 3: reconnect — ORDER MATTERS
prevNode.next.next = curr;   // old B (now tail) → node after C
prevNode.next = prev;        // node before B → old C (now head)

return dummy.next;

Critical order: tail first, then head. prevNode.next still points to old B (the tail) at step 3a. Once step 3b runs, that reference is overwritten — so if you do 3b first, you lose the tail pointer forever.

reverseKGroup — recursive structure
ListNode reverseKGroup(ListNode head, int k) {
    // 1. Count k nodes — return as-is if fewer than k remain
    check = head;  count = 0;
    while (check != null && count < k) { check = check.next; count++; }
    if (count < k) return head;

    // 2. Reverse exactly k nodes (standard 3-pointer)
    curr = head;  prev = null;
    for (i = 0; i < k; i++) {
        next = curr.next;  curr.next = prev;  prev = curr;  curr = next;
    }
    // 3. head is now the tail of the reversed segment
    //    curr is the first node of the remaining list
    head.next = reverseKGroup(curr, k);   // connect tail to next reversed group
    return prev;                           // prev is the new head
}
deleteNode — copy-next trick (no predecessor available)
node.val  = node.next.val;        // copy value from the next node
node.next = node.next.next;       // skip the next node

This effectively "erases" node.next by overwriting node's value. Works only if node is not the tail. Creating a new node and swapping references won't work — external pointers still hold the old node's address.

removeNthFromEnd — two-pointer gap pattern (optimal)
// Optimal O(N) single-pass:
dummy.next = head;
fast = dummy;  slow = dummy;
for (i = 0; i < N; i++) fast = fast.next;   // advance fast N steps
while (fast.next != null) { fast = fast.next; slow = slow.next; }
slow.next = slow.next.next;   // delete Nth from end
return dummy.next;

When fast reaches the last node, slow is exactly N steps behind — pointing to the predecessor of the node to delete.

deleteDuplicates — in-place vs new list

In-place (O(1) space): when curr.val == curr.next.val, do curr.next = curr.next.next. Do NOT advance curr — the new next might also be a duplicate. Advance curr only when the value changes.

Clone List with Random Pointer — 2-Pass HashMap d25 ▼
Why a HashMap

The random pointer can target any node anywhere in the list. When wiring the clone's random pointer, you need instant access to the clone of an arbitrary original node. HashMap gives O(1) lookup: original → clone.

Skeleton
// Pass 1: create all clones, build map (values only — no links yet)
Map<Node, Node> store = new HashMap<>();
curr = head;
while (curr != null) {
    store.put(curr, new Node(curr.val));
    curr = curr.next;
}

// Pass 2: wire next and random using map lookups
curr = head;
while (curr != null) {
    store.get(curr).next   = store.get(curr.next);    // null-key safe
    store.get(curr).random = store.get(curr.random);  // null-key safe
    curr = curr.next;
}
return store.get(head);

Null-safe: HashMap.get(null) returns null (does not throw). So store.get(curr.next) when curr.next is null safely returns null — no explicit null check needed.

Wrong pattern: clone.next = curr.next points the clone's next to the original node, not another clone. Always go through the map.

Stack — Matching, Evaluation, Cancellation d26 ▼
Signals

Pairs that must open and close in order (brackets). Postfix expression evaluation. Adjacent elements that cancel (double char trouble). You need the most recently seen unprocessed item.

Skeleton

Walk left to right. On opening/value → push. On closing/operator → pop and process. After the full pass, an empty stack means everything balanced. Always check isEmpty() before pop/peek. For postfix: pop two operands, apply operator, push result back.

Redundant braces variant

Push all characters. On ): pop until (; track whether any operator (+−×÷) was seen among the popped items. No operator found → those braces are redundant. Track the flag inside the pop loop.

Monotonic Stack — Nearest Smaller / Greater d27 ▼
Signals

"For each element, find the nearest to its left/right that is smaller/greater." Rectangle areas or contributions bounded by the nearest boundary element. The answer for each index depends on the first element that breaks a monotone order.

Skeleton — next smaller to the right
Deque<Integer> stack = new ArrayDeque<>();   // stores indices
int[] result = new int[N];
Arrays.fill(result, -1);    // default: no smaller to the right

for (int i = 0; i < N; i++) {
    while (!stack.isEmpty() && a[stack.peek()] > a[i]) {
        result[stack.pop()] = i;   // i is the next smaller for that index
    }
    stack.push(i);
}
// stack still has indices with no smaller to the right → result stays -1

Push indices, not values. The value at popped index j found its answer at i. Distance = i − j if needed.

Largest rectangle in histogram

For each bar, find NSL (next smaller left) and NSR (next smaller right) using monotonic stack. Width = NSR[i] − NSL[i] − 1. Area = height[i] × width. Track max.

Queue / Deque — Sliding Window Max d28 ▼
Signals

Fixed-size window slides across an array. Need max or min at each position. Elements expire after a fixed number of steps.

Skeleton — sliding window maximum
Deque<Integer> dq = new ArrayDeque<>();   // stores indices, front = current max index
for (int i = 0; i < N; i++) {
    // remove back while current element is ≥ back (back is useless)
    while (!dq.isEmpty() && a[dq.peekLast()] <= a[i]) dq.pollLast();
    dq.addLast(i);
    // remove front if it's outside the window
    if (dq.peekFirst() < i - K + 1) dq.pollFirst();
    // front is the window's max
    if (i >= K - 1) result[i - K + 1] = a[dq.peekFirst()];
}

Deque stores indices in decreasing order of their values. Front is always the maximum of the current window.

Tree Recursion / DFS d29, d30 ▼
Signals

Same logic applies at every subtree. Answer = combine(left result, right result, current node). Path problems, subtree sums, structural checks (balanced, symmetric, equal partition).

Standard skeleton
int solve(TreeNode node) {
    if (node == null) return NEUTRAL;   // 0 for sums, true for checks, etc.
    int left  = solve(node.left);
    int right = solve(node.right);
    // check for failure sentinel before combining (e.g. isBalanced returns -1)
    if (left == SENTINEL || right == SENTINEL) return SENTINEL;
    return combine(left, right, node.val);
}
isBalanced — sentinel pattern

Return actual height normally. Return -1 when unbalanced. Every recursive call checks: if (left == -1 || right == -1) return -1 before computing own height. Do NOT check the sentinel after the fact — check before using the value.

Build tree from inorder + pre/postorder

Preorder[0] (or postorder[last]) is always the root. Find that root in inorder — everything to its left is the left subtree, everything to its right is the right subtree. The count of elements in the left subtree from inorder controls all index slicing for the recursive calls.

BST — Search, Validate, Build d31 ▼
Signals

Tree has left < root < right ordering. Search in O(log N) average. Validate ordering. Build balanced structure from sorted input.

Search
TreeNode search(TreeNode root, int val) {
    if (root == null || root.val == val) return root;
    return val < root.val ? search(root.left, val) : search(root.right, val);
}
Validate — bound propagation
boolean isValid(TreeNode node, long min, long max) {
    if (node == null) return true;
    if (node.val <= min || node.val >= max) return false;
    return isValid(node.left, min, node.val)
        && isValid(node.right, node.val, max);
}
// initial call: isValid(root, Long.MIN_VALUE, Long.MAX_VALUE)

Use long bounds — nodes can hold Integer.MIN/MAX_VALUE, and int bounds cannot express "less than MIN" or "greater than MAX".

Build balanced BST from sorted array
TreeNode convert(int[] a, int lo, int hi) {
    if (lo > hi) return null;
    int mid = lo + (hi - lo) / 2;
    TreeNode root = new TreeNode(a[mid]);
    root.left  = convert(a, lo, mid - 1);
    root.right = convert(a, mid + 1, hi);
    return root;
}
// initial call: convert(a, 0, a.length - 1)

Always pick mid as root. This ensures left and right subtrees differ in size by at most 1, keeping the tree balanced.
