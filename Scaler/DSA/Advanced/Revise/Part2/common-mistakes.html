Common Mistakes
Part 2 · Days 21–31
Generic pitfalls by technique — not edge cases per problem.
Binary Search
Wrong mid calculation — integer overflow
Writing (low + high) / 2 works until both values are large integers — their sum wraps and gives a negative mid. Always write low + (high - low) / 2.
Wrong loop condition — missing the last element
Using while (low < high) exits one step early. The answer can sit exactly where low == high, and a strict < skips that position entirely. Use while (low <= high).
Not shrinking the range — infinite loop
Writing low = mid or high = mid without ±1 means the range never shrinks when low and high are adjacent. The loop spins forever. Always write low = mid + 1 or high = mid - 1.
Returning on first match instead of continuing
The moment you find the target and return, you get one arbitrary occurrence. For leftmost: save mid, keep going left (high = mid - 1). For rightmost: save mid, keep going right (low = mid + 1).
Checking only one side of lower_bound
lower_bound gives the first index ≥ target. The truly closest element could be just before that index. Always check both lb and lb - 1 and take the smaller absolute difference.
Linked List
Losing the rest of the list before relinking
Redirecting curr.next before saving where it pointed loses everything after. Save the next pointer first, then redirect.
Treating head deletion as a special case
Deleting the head requires returning a new head. Use a dummy node before the real head — then head deletion is just "delete the next of dummy", same as any other node.
Stack
Calling pop or peek without checking isEmpty
An empty stack throws or returns garbage. Always check isEmpty() before every pop and peek — no exceptions.
Matching the wrong bracket pair
When a closing bracket arrives, the stack top must be the exact corresponding open bracket. Checking only that the stack is non-empty lets mismatched pairs pass silently.
Forgetting that the operator determines redundancy
In redundant-braces problems, after popping to the matching (, if no operator was found among the popped items those braces are redundant. Check inside the pop loop, not after it.
Trees
Accessing a child without checking for null first
Calling node.left.val without confirming node.left != null crashes immediately. Handle null as the very first thing in every recursive function.
Using int bounds for BST validation
Passing Integer.MIN_VALUE / Integer.MAX_VALUE as initial bounds fails when a node holds exactly those values. Use Long.MIN_VALUE / Long.MAX_VALUE.
Off-by-one in tree construction from two traversals
The number of nodes in the left subtree drives every index arithmetic when building from inorder + pre/postorder. Being off by one silently builds the wrong tree with no error thrown.
Not propagating the failure sentinel upward
When a helper returns -1 to signal failure (e.g. subtree is unbalanced), every parent call must check for -1 before computing its own result. Skipping the check produces a wrong answer that looks like success.
