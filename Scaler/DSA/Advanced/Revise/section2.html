How to approach

6 thinking cues · 8 patterns · 7 formulas · 18 problems
how to think about this topic
1. Is the input (or the answer space) monotonic?

Sorted arrays are the obvious case. The deeper trick: if you can frame the problem as 'what is the smallest/largest X such that predicate(X) is true?' and predicate is monotonic in X, binary search works on the answer.

2. Define the search space precisely.

low and high must bracket the answer. For BS on answer, low = minimum feasible, high = maximum feasible. Get this wrong and you'll loop forever or miss the answer.

3. Write a clean predicate / check function.

Extract the feasibility check into a private boolean method (canPlaceCows, isPaintingCompletionPossible, canBeAllotted). Keep the binary search loop dumb — it just shrinks the range.

4. Decide which side to shrink on success.

Maximize answer (aggressive cows): on success, store result and try larger → low = mid + 1. Minimize answer (painter's partition): on success, store result and try smaller → high = mid - 1. The 'store result on every success' pattern is bulletproof.

5. Pick the loop invariant: low <= high.

Default to while (low <= high), exit when low > high, return the stored answer. Avoid low < high unless you have a strong reason — it requires careful mid-update logic.

6. Watch overflow and types.

mid = low + (high - low) / 2 — never (low + high) / 2. For mid * mid, use long. For sums (painter, allocate), totals can exceed int.

Find Left Most and Right Most Index of Element

Lower / Upper Bound
Binary SearchLower BoundUpper BoundDuplicates

Given a sorted array A of size N and an integer B, return [firstIndex(B), lastIndex(B)]. If B is absent return [-1, -1]. Must be O(log N).

sample input
A = [5, 7, 7, 8, 8, 10]
B = 8
sample output
[3, 4]
in plain english

The array is sorted, so all copies of B sit in a contiguous block. You need the block's first index and last index. Run two near-identical binary searches: the first one — whenever it finds B — stores the index and then keeps searching the LEFT half to pull the answer earlier; the second one — whenever it finds B — stores the index and keeps searching the RIGHT half to push it later. If B is missing entirely, both stay at -1.

how to think
  • Sorted input + 'first and last position' screams binary search, not a linear scan.
  • Equal copies sit in one block, so you just need its two edges.
  • Run the same search twice: one biased left for the first index, one biased right for the last.
  • The trick is the 'equal' branch: don't stop on a hit, keep shrinking toward the edge you want.
how to proceed — pseudocodetime O(log N) · space O(1)
BS1 → on hit: store first, high = mid - 1
BS2 → on hit: store last,  low  = mid + 1
Brute O(N)  →  Optimal O(log N)
watch out
  • Don't return on the first match — that gives some middle index, not an edge.
  • Empty array must return `[-1, -1]` before the loop runs.
  • If `first` stays -1, B is absent — return `[-1, -1]`, don't trust `last`.
answer — optimal code (java)
public int[] searchForStartAndEndIndexOfAnElementInAnArray(int[] A, int B) {
    int N = A.length;
    int[] result = new int[]{ -1, -1 };
    if (N == 0) {
        return result;
    }

    int low = 0, high = N - 1, first = -1, last = -1;

    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (A[mid] < B) {
            low = mid + 1;
        } else if (A[mid] > B) {
            high = mid - 1;
        } else {
            first = mid;
            high = mid - 1;
        }
    }

    low = 0;
    high = N - 1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (A[mid] < B) {
            low = mid + 1;
        } else if (A[mid] > B) {
            high = mid - 1;
        } else {
            last = mid;
            low = mid + 1;
        }
    }

    if (first != -1) {
        result[0] = first;
        result[1] = last;
    }
    return result;
}

Search Insert Position (Lower Bound)

Lower Bound
Binary SearchLower BoundInsert Position

Sorted A, target B. If B exists return its index, else return the index of the smallest element ≥ B (or N if all are smaller).

sample input
A = [1, 3, 5, 6]
B = 5
sample output
2
in plain english

You're given a sorted array and a number B. If B already sits in the array, return its index. If it doesn't, return the index where it would slot in to keep things sorted — that is, the index of the first element that's at least B (or N if every element is smaller than B). This is the classic lower_bound problem in disguise.

how to think
  • 'Find where it fits to stay sorted' is the lower_bound signal — binary search, not a scan.
  • Reframe it as 'smallest index where `A[i] >= B`' — that boundary is your answer.
  • On a hit-or-bigger, store the candidate and keep searching left for an earlier one.
  • A sentinel `res = N` quietly handles 'everything is smaller, insert at end'.
how to proceed — pseudocodetime O(log N) · space O(1)
ans = N
while low <= high:
  if A[mid] < B  → low = mid + 1
  else           → ans = mid, high = mid - 1
return ans
Brute O(N)  →  Optimal O(log N)
watch out
  • Forget the `res = N` sentinel and the 'larger than all' case breaks.
  • Don't return -1 when absent — the insert position is a real index, not 'not found'.
  • On `A[mid] > B` you must pull `high = mid - 1`, else you miss an earlier slot.
answer — optimal code (java)
public int positionWhereTargetIsPresentOrShouldBeInserted(int[] A, int B) {
    int N = A.length;
    int low = 0, high = N - 1, res = N;

    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (A[mid] < B) {
            low = mid + 1;
        } else if (A[mid] > B) {
            res = mid;
            high = mid - 1;
        } else {
            return mid;
        }
    }
    return res;
}

Single Element in Sorted Array

BS on Pattern
Binary SearchPatternIndex ParityXOR Alternative

Every element appears twice in sorted order, except one unique element. Find it in O(log N).

sample input
A = [1, 1, 2, 2, 3, 3, 4, 5, 5]
sample output
4
in plain english

Every value appears exactly twice except one. Because the array is sorted, pairs sit next to each other: positions (0,1), (2,3), (4,5)... — first index of each pair is even. The moment the unique element appears, it shoves every subsequent pair one slot to the right, so afterwards pairs start at odd indices. Binary search the index where this parity flips.

how to think
  • O(log N) on a sorted array with pairs = binary search, even though there's no target.
  • The clue is index parity: before the loner, pairs start at even indices; after it, they shift.
  • So the question becomes 'is the pattern still intact at mid?' — that's your monotonic predicate.
  • Check which neighbour matches, then use even/odd of the pair start to pick a side.
how to proceed — pseudocodetime O(log N) · space O(1)
Handle 1-element and boundary loners first.
Loop with low=1, high=N-2:
  if A[mid] == A[mid+1]:
    if mid is even → unique is on the right (low = mid + 2)
    else           → unique is on the left  (high = mid - 1)
  else if A[mid] == A[mid-1]:
    same logic with mid -= 1
  else return A[mid]
Brute O(N)  →  Optimal O(log N)  →  Alternative — XOR O(N)
watch out
  • Handle N==1 and both edges first, or `A[mid+1]` / `A[mid-1]` reads out of bounds.
  • Search the interior only: `low = 1, high = N - 2`.
  • Get the even/odd direction backwards and you walk away from the loner.
answer — optimal code (java)
public int singleElementInASortedArray(int[] A) {
    int N = A.length;
    if (N == 1) {
        return A[0];
    }
    if (A[0] != A[1]) {
        return A[0];
    }
    if (A[N - 1] != A[N - 2]) {
        return A[N - 1];
    }

    int low = 1, high = N - 2;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (A[mid] == A[mid + 1]) {
            if (mid % 2 == 0) {
                low = mid + 2;
            } else {
                high = mid - 1;
            }
        } else if (A[mid] == A[mid - 1]) {
            int pairStart = mid - 1;
            if (pairStart % 2 == 0) {
                low = pairStart + 2;
            } else {
                high = pairStart - 1;
            }
        } else {
            return A[mid];
        }
    }
    return -1;
}

Find a Peak Element

BS on Unimodal
Binary SearchPeakUnimodalGradient

Find any element ≥ both neighbours. Corners count if they beat their one neighbour. Guaranteed a single peak. Solve in O(log N).

sample input
A = [5, 17, 100, 11]
sample output
100
in plain english

You're standing somewhere on the array. Look at the value to your left and the value to your right. Whichever side goes UP — walk that way. Keep doing this and you must reach a peak, because the array can't climb forever. Binary search lets you take giant uphill steps instead of one-by-one.

how to think
  • 'Rises then falls, find the top' is a unimodal shape — binary search on the slope.
  • You don't need the array sorted; you just need to know which way is uphill.
  • If `A[mid]` beats both neighbours you're done; otherwise climb toward the taller side.
  • The rising side always hides a peak, so move there.
how to proceed — pseudocodetime O(log N) · space O(1)
Pre-check both boundaries.
Loop low=1, high=N-2:
  if A[mid] beats both neighbours → return A[mid]
  else if A[mid] > A[mid-1]      → climbing, go right
  else                            → descending, go left
Brute O(N)  →  Optimal O(log N)
watch out
  • Pre-check N==1 and both corners so `mid-1` / `mid+1` never go out of bounds.
  • Restrict the loop to `low = 1, high = N - 2`.
  • Always move toward the increasing neighbour, or you drift off the peak.
answer — optimal code (java)
public int peakElement(int[] A) {
    int N = A.length;
    if (N == 1) {
        return A[0];
    }
    if (A[0] >= A[1]) {
        return A[0];
    }
    if (A[N - 1] >= A[N - 2]) {
        return A[N - 1];
    }

    int low = 1, high = N - 2;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (A[mid] > A[mid + 1] && A[mid] > A[mid - 1]) {
            return A[mid];
        } else if (A[mid] > A[mid - 1]) {
            low = mid + 1;
        } else {
            high = mid - 1;
        }
    }
    return -1;
}

Matrix Search

BS on 2D Matrix
Binary Search2D MatrixSorted MatrixFlat Indexing

N×M matrix, rows sorted left-to-right, each row's first element ≥ previous row's last. Return 1 if B exists, else 0.

sample input
A = [[1, 3, 5, 7],
     [10, 11, 16, 20],
     [23, 30, 34, 50]]
B = 30
sample output
1
in plain english

The matrix has a special property: rows are sorted left-to-right, and each row's first element is strictly greater than the previous row's last element. That means if you imagine the matrix flattened row by row, the result is one long sorted sequence of length N*M. Run an ordinary binary search on the indices 0..N*M-1; convert each midpoint index back to (row, col) with row = mid/M and col = mid%M.

how to think
  • Rows sorted and each row starts after the previous ends = the matrix is one big sorted list.
  • That global sort is the binary-search signal — flatten it, don't scan row by row.
  • Treat indices `0 .. N*M-1` as a 1D array over the grid.
  • Map `mid` back with `r = mid / M`, `c = mid % M` and compare as usual.
how to proceed — pseudocodetime O(log(N*M)) · space O(1)
low = 0, high = N*M - 1
while low <= high:
  mid = ...; r = mid/M; c = mid%M
  compare A[r][c] with B and shrink as usual
Optimal O(log(N*M))
watch out
  • Mixing up `/ M` vs `% M` for row/col sends you to the wrong cell.
  • `N*M` can overflow int for a big matrix — mind the product.
  • Return 0 (absent), not -1, when the loop exits — the problem wants a 0/1 flag.
answer — optimal code (java)
public int searhAMatrix(int[][] A, int B) {
    int N = A.length, M = A[0].length;
    int low = 0, high = (N * M) - 1;

    while (low <= high) {
        int mid = low + (high - low) / 2;
        int r = mid / M, c = mid % M;
        if (A[r][c] == B) {
            return 1;
        } else if (A[r][c] < B) {
            low = mid + 1;
        } else {
            high = mid - 1;
        }
    }
    return 0;
}

Minimum Difference

BS + Sorting (Closest Element)
Binary SearchLower BoundMatrixSorting

Matrix C of A×B. For each adjacent row pair, find the minimum absolute difference between any element of row i and any element of row i+1. Return the smallest such diff.

sample input
A = 3, B = 2
C = [[7, 3], [2, 1], [4, 9]]
sample output
1
in plain english

You have a matrix of A rows and B columns. For every adjacent pair of rows, you need the smallest absolute difference between any value in row i and any value in row i+1. Sort each row first so you can binary search inside. Then, for every value v in row i, find its closest neighbour in row i+1 — that's one of two candidates: the first value >= v (lower_bound) or the value just before it. Track the minimum globally across every (i, j) pair.

how to think
  • 'Closest element across two rows' is a lower_bound job once each row is sorted.
  • Sort every row first — that unlocks binary search per lookup.
  • For each value, lower_bound in the next row gives the closest element that's `>=` it.
  • The closest smaller one sits right before it, so check both `lb` and `lb-1`.
how to proceed — pseudocodetime O(A · B · log B) · space O(1)
sort each row
for each i, j:
  lb = lower_bound(C[i+1], C[i][j])
  consider |C[i][j] - C[i+1][lb]|     (closest greater)
  consider |C[i][j] - C[i+1][lb-1]|   (closest smaller)
  update ans = min
Optimal O(A · B · log B)
watch out
  • Guard the bounds: only use `lb` if `lb < B`, only use `lb-1` if `lb > 0`.
  • Forget to sort the rows and the lower_bound is meaningless.
  • Start `ans` at a large sentinel so the first real diff always wins.
answer — optimal code (java)
public int minimumCostToBuildAnArray(int A, int B, int[][] C) {
    int ans = 1_000_000_000;
    for (int i = 0; i < A; i++) {
        Arrays.sort(C[i]);
    }

    for (int i = 0; i < A - 1; i++) {
        for (int j = 0; j < B; j++) {
            int lb = lowerBound(C[i + 1], C[i][j]);
            if (lb != B) {
                ans = Math.min(ans, Math.abs(C[i][j] - C[i + 1][lb]));
            }
            if (lb != 0) {
                ans = Math.min(ans, Math.abs(C[i][j] - C[i + 1][lb - 1]));
            }
        }
    }
    return ans;
}

private int lowerBound(int[] a, int val) {
    int low = 0, high = a.length - 1, ans = a.length;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (a[mid] < val) {
            low = mid + 1;
        } else {
            ans = mid;
            high = mid - 1;
        }
    }
    return ans;
}

Maximum Height of Staircase

BS on Answer (Math)
Binary SearchBS on AnswerMathSum Formula

Given A blocks, build max-height staircase where stair i needs i blocks. Find max h such that 1+2+...+h ≤ A.

sample input
A = 20
sample output
5
in plain english

You have A blocks. A staircase of height h needs 1 block for stair 1, 2 for stair 2, and so on — total h*(h+1)/2 blocks. Find the largest h for which h*(h+1)/2 is still no more than A. As h grows, the cost grows monotonically, so binary searching h works perfectly.

how to think
  • 'Max h such that 1+2+...+h <= A' is binary search on the answer, not a formula hunt.
  • The sum `h*(h+1)/2` grows monotonically in h — that's the predicate that flips once.
  • Search for the largest feasible h: on success store it and try bigger.
  • Bound high near `sqrt(2A)` so you don't waste iterations.
how to proceed — pseudocodetime O(log A) · space O(1)
low=0, high=sqrt(2A)+1; find max h with h*(h+1)/2 <= A
Brute (greedy walk) O(√A)  →  Optimal (BS on answer) O(log A)
watch out
  • `mid*(mid+1)` overflows int — use `long` for low, high, mid.
  • This maximizes, so on success go right (`low = mid + 1`), not left.
  • Store the answer on every success; the loop-exit values aren't reliable.
answer — optimal code (java)
public int staircaseBS(int A) {
    long low = 0, high = (long) Math.sqrt(2.0 * A) + 1, ans = 0;
    while (low <= high) {
        long mid = low + (high - low) / 2;
        if (mid * (mid + 1) / 2 <= A) {
            ans = mid;
            low = mid + 1;
        } else {
            high = mid - 1;
        }
    }
    return (int) ans;
}

3
in plain english

Compute floor(sqrt(A)) without using Math.sqrt. The largest x with x*x <= A is the answer. Because A can be up to 1e9, mid*mid would overflow a 32-bit int, so promote to long before multiplying. Binary search x over [1, A/2] (any value above A/2 squared overflows A for A >= 4).

  • 'Max K such that no window of size K exceeds B' is binary search on the answer K.
  • If size K is safe, every smaller size is too — that monotonicity is what BS needs.
  • Check a candidate K with a sliding-window sum in O(N).
  • On all-windows-ok, store K and try a bigger window.

public int maxSubArrayFactorLessThanB(int[] nums, int sum) {
    int low = 0, high = nums.length, K = -1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (subArrayOk(nums, sum, mid)) {
            K = mid;
            low = mid + 1;
        } else {
            high = mid - 1;
        }
    }
    return K;
}

private boolean subArrayOk(int[] nums, int sum, int K) {
    if (K == 0) {
        return true;
    }
    long windowSum = 0;
    for (int i = 0; i < K; i++) {
        windowSum += nums[i];
    }
    if (windowSum > sum) {
        return false;
    }

    for (int i = K; i < nums.length; i++) {
        windowSum += nums[i] - nums[i - K];
        if (windowSum > sum) {
            return false;
        }
    }
    return true;
}

SECTION 2 · STACKS

How to approach

6 thinking cues · 8 patterns · 4 formulas · 14 problems
how to think about this topic
1. When to Think Stack

Use a stack when: (a) you need to match or validate nested structures (parentheses, brackets, tags), (b) you're traversing a sequence and need to 'look back' at recent elements that may become irrelevant, (c) you need nearest smaller/greater element to left or right, (d) you're converting or evaluating expressions with operator precedence, (e) you need to track cumulative state through nested contexts (like sign tracking through brackets), or (f) you're simulating recursion iteratively. If the problem mentions 'most recent', 'matching pairs', 'eliminate', or 'next/prev greater/smaller', think stack.

2. Monotonic Stack Pattern

A monotonic stack maintains elements in increasing or decreasing order. When a new element violates the order, pop until restored, then push the new element. This eliminates 'useless' candidates in O(1) amortized per element. Monotonic increasing stack finds nearest smaller elements (left: iterate left-to-right, right: iterate right-to-left). Monotonic decreasing stack finds nearest greater elements. Key insight: each element is pushed and popped at most once, giving O(N) total time. Store indices (not values) when you need distance/position information (e.g., histogram width calculation). Store values when you only need the value itself (e.g., next greater element).

3. Histogram Pattern

For histogram-based max rectangle problems: for each bar i, find the maximum width where it is the shortest bar. Compute prevSmaller[i] (nearest smaller bar to left, or -1) and nextSmaller[i] (nearest smaller bar to right, or N) using monotonic stacks. Width = nextSmaller[i] - prevSmaller[i] - 1. Area = height[i] × width. Track max area. For binary matrix rectangles, treat each row as histogram base: height[j] = consecutive 1s from current row upward in column j. Run histogram algorithm for each row. Key: reuse the histogram machinery—don't reinvent max rectangle logic.

4. Expression Parsing & Conversion

For balanced parentheses: push opening brackets, pop and match on closing brackets. If stack empty on close or mismatch, return invalid. For infix to postfix: operands → output immediately; operators → pop all from stack with >= precedence (don't pop past '('), then push current operator; '(' → push as wall; ')' → pop until '(' found, discard '('. For expression comparison (e.g., check two bracket expressions): track cumulative sign through nested brackets using stack. Stack holds context (current sign multiplier). '(' inherits context: stack.push(stack.peek() × currentSign). Variable records: sign[var] = stack.peek() × currentSign. Compare sign arrays for equivalence.

5. Contribution Technique

For subarray contribution problems (e.g., sum of max-min across all subarrays): each element contributes to multiple subarrays. Count how many subarrays have element i as max/min. Use four monotonic stacks to compute prevSmaller, nextSmaller, prevGreater, nextGreater. Count as max = (i - prevGreater[i]) × (nextGreater[i] - i). Count as min = (i - prevSmaller[i]) × (nextSmaller[i] - i). Contribution[i] = A[i] × (count as max - count as min). Sum all contributions modulo MOD. This reduces brute force O(N²) or O(N³) to O(N).

6. Two-Stack Design Patterns

Min Stack: maintain two parallel stacks—main stack holds values, min stack holds running minimum. On push(val), push val to main, push min(val, minStack.peek()) to min stack. On pop, pop from both. getMin() returns minStack.peek(). All ops O(1). Sort Stack: use auxiliary sorted stack. Pop from input, find correct position in sorted (pop larger elements back to input temporarily), push element, restore elements from input to sorted. O(N²) time but O(N) space. Key: sorted stack maintains invariant—always ascending/descending. Transfer logic handles insertion sort behavior.

  • Operators come after their operands, and each operator needs the two most recent values -> stack.

Stack Simulation

There is a football event going on in your city. In this event, you are given A passes and players having ids between 1 and 10⁶.

Initially, some player with a given id had the ball in his possession. You have to make a program to display the id of the player who possessed the ball after exactly A passes.

There are two kinds of passes:
1) ID
2) 0

For the first kind of pass, the player in possession of the ball passes the ball "forward" to the player with id = ID.
For the second kind of pass, the player in possession of the ball passes the ball back to the player who had forwarded the ball to him.

In the second kind of pass "0" just means Back Pass.
Return the ID of the player who currently possesses the ball.

sample input
A = 10, B = 23, C = [86, 63, 60, 0, 47, 0, 99, 9, 0, 0]
sample output
63
in plain english

Start with the initial player B on the stack. Process each pass in array C. If C[i] is a player ID (not 0), it's a forward pass—push that player ID onto the stack. If C[i] is 0, it's a back pass—pop the stack to remove the current player, and the new top is who now has the ball. After all A passes, return the top of the stack (current ball holder).

how to think
  • Back-pass returns the ball to whoever gave it -> undo/history behavior -> stack.
  • Forward pass to an id -> push it; back pass (0) -> pop and the new top holds the ball.
  • The realization: the stack is the chain of possession, top = current holder.
  • Answer is the top after all passes.
how to proceed — pseudocodetime O(A) · space O(A)
stack = empty
stack.push(B)
currentPlayer = B
for i = 0 to A-1:
  if C[i] == 0:
    stack.pop()
    currentPlayer = stack.peek()
  else:
    currentPlayer = C[i]
    stack.push(C[i])
return currentPlayer
Optimal O(A)
watch out
  • Push the starting player B first so a back pass has something beneath it.
  • On a back pass, pop then read the new top; don't return the popped value.
  • A pass value of 0 means back, any other value is a forward pass id.
answer — optimal code (java)
public int passingGameOfBall(int A, int B, int[] C) {
    Stack<Integer> stack = new Stack<>();
    stack.push(B);
    int currentPlayer = B;
    for (int i = 0; i < A; i++) {
        if (C[i] == 0) {
            stack.pop();
            currentPlayer = stack.peek();
        } else {
            currentPlayer = C[i];
            stack.push(C[i]);
        }
    }
    return currentPlayer;
}

+ and - have equal precedence and lowest precedence among given operators.

"abcd^e-fgh*+^*+i-"
in plain english

When you see an operator, pop from the stack all operators with greater or equal precedence and append them to output, then push the current operator. Opening brackets push as walls. Closing brackets pop everything until the matching opening bracket. After scanning, pop remaining operators. The result is the postfix expression.

how to think
  • Reordering by operator precedence -> operators wait on a stack until something forces them out.
  • Operands go straight to output; operators pop everything of `>=` precedence first, then push.
  • `(` is a wall you push; `)` flushes operators until the matching `(`.
  • At the end, drain the stack into the output.
how to proceed — pseudocodetime O(N) · space O(N)

stack = empty
for c in A:
  if isOperand(c): output += c
  elif c == '(': stack.push(c)
  elif c == ')':
    while stack.peek() != '(': output += stack.pop()
    stack.pop()  // remove '('
  else:  // operator
    while !stack.isEmpty() && stack.peek() != '(' && prec(stack.peek()) >= prec(c):
      output += stack.pop()
    stack.push(c)
while !stack.isEmpty(): output += stack.pop()
return output
Optimal O(N)

  • Use `>=`, not `>`, so equal-precedence left-associative operators pop correctly.
  • Never pop past a `(` when handling an operator; it's a wall.
  • Discard the `(` after flushing on `)`; don't append it to output.
  • Drain any operators still on the stack after the scan finishes.
answer — optimal code (java)
public String infixToPostfix(String A) {
    StringBuilder postfix = new StringBuilder();
    Stack<Character> stk = new Stack<>();
    for (char c : A.toCharArray()) {
        if (Character.isLetterOrDigit(c)) {
            postfix.append(c);
        } else if (c == '(') {
            stk.push(c);
        } else if (c == ')') {
            while (!stk.isEmpty() && stk.peek() != '(') {
                postfix.append(stk.pop());
            }
            stk.pop();
        } else {
            while (!stk.isEmpty() && stk.peek() != '(' && precedence(stk.peek()) >= precedence(c)) {
                postfix.append(stk.pop());
            }
            stk.push(c);
        }
    }
    while (!stk.isEmpty()) {
        postfix.append(stk.pop());
    }
    return postfix.toString();
}

    switch (c) {
        case '^': return 3;
        case '*':
        case '/': return 2;
        case '+':
        case '-': return 1;
        default: return 0;
    }
}

The value of an array is computed as the difference between the maximum element in the array and the minimum element in the array A.

0
in plain english

how to think
  • Sum over all subarrays -> don't enumerate; count each element's contribution -> monotonic stacks.
  • An element counts as max in some subarrays and min in others; find both boundary spans.
  • Need four arrays: prevGreater/nextGreater (for max) and prevSmaller/nextSmaller (for min).
  • Contribution = `A[i] x (countAsMax - countAsMin)`, summed mod 1e9+7.
how to proceed — pseudocodetime O(N) · space O(N)
prevSmaller = computePrevSmaller(A)
nextSmaller = computeNextSmaller(A)
prevGreater = computePrevGreater(A)
nextGreater = computeNextGreater(A)
sum = 0
for i = 0 to N-1:

  countMin = (i - prevSmaller[i]) * (nextSmaller[i] - i)

    prevSmaller[0] = -1;
    stack.push(0);

        while (heights[stack.peek()] >= heights[i]) {
            stack.pop();
            if (stack.isEmpty()) {
                prevSmaller[i] = -1;
                break;
            }
        }
        if (!stack.isEmpty()) {
            prevSmaller[i] = stack.peek();
        }
        stack.push(i);

How to approach

how to think about this topic
1. When to Use a Queue vs Deque

Use a plain queue (FIFO only) for simple BFS, level-order traversal, or task scheduling where you only need push-back and pop-front. Use a deque (double-ended) when you need to access or modify both ends: sliding window problems (remove from front as window slides, add to back), monotonic deque patterns (evict from back when maintaining max/min), or implementing queue with stacks (transfer elements by reversing). Deque is the Swiss Army knife — use it by default unless you're certain you only need one end.

2. Monotonic Deque Pattern (Sliding Window Max/Min)

For sliding window maximum: maintain deque in DECREASING order of values. When a new element arrives, remove all smaller elements from the back (they can never be max anymore). The front always holds the max. For minimum: maintain INCREASING order and remove larger elements. Use indices, not values, so you can check if the front is out of the window. This pattern converts O(N·K) brute force (N windows, K elements each) to O(N) (each element enters/leaves deque once). The key insight: when a larger element arrives, all smaller elements before it become irrelevant for future windows.

3. Queue Using Two Stacks (Amortized O(1))

Two stacks simulate a queue: inputStack (receives pushes), outputStack (serves pops/peeks). Push goes to inputStack. Pop/peek from outputStack; if empty, transfer all elements from inputStack to outputStack (this reverses the stack, making LIFO → FIFO). Each element is moved at most twice (input → output), so all operations are amortized O(1). The lazy transfer (only when output is empty) is crucial for amortization. This pattern is essential when you need queue behavior but only have stack primitives (or when designing data structures with limited operations).

4. BFS Generation with Queue (Number/String Generation)

Think of the problem as exploring an implicit tree level by level. Start with seed values in the queue. For each dequeue, that's the next answer — then generate children and enqueue them. The queue's FIFO property ensures you explore levels in order, which often translates to ascending order (numbers) or lexicographic order (strings). Example: generating numbers with digits 1,2,3 → seeds [1,2,3], each spawns [X1, X2, X3] by appending. Queue naturally maintains sorted order because smaller numbers are enqueued earlier.

5. Stream Processing (First Non-Repeating Character)

For stream problems (process elements one by one, answer query after each): combine a deque (maintains order of candidates) with a HashMap (tracks frequencies). Add new elements to the deque if they're fresh. After each addition, clean the deque front by removing elements whose frequency > threshold (e.g., > 1 for non-repeating). The cleaned front is the answer. This lazy deletion pattern is O(N) total because each element enters and leaves the deque at most once. The deque holds potential answers, the map filters them.

6. Two-Deque Pattern (Simultaneous Min and Max)

For problems needing both min and max in a sliding window, use two independent deques in parallel: one decreasing (max), one increasing (min). Both use the same window maintenance logic (remove stale indices from front, add new index to back, evict incompatible elements from back). At each window position, front of maxDeque = max, front of minDeque = min. This pattern is O(N) because each element enters/leaves each deque once. Common in problems asking for sum/product/range of min+max across all windows.

in plain english

You need to find the maximum element in every window of size B as you slide across the array. Use a deque (double-ended queue) to store indices of array elements in decreasing order of their values. For each new element, remove all smaller elements from the back (they can never be the max now), then add the new element. The front of the deque always holds the index of the maximum element in the current window.

how to think
  • "Max of every window of size B" is the tell: don't re-scan each window, use a monotonic deque.
  • Keep the deque decreasing; a bigger new element makes all smaller ones behind it useless, so drop them from the back.
  • The front is always the current window's max. Store indices, not values, so you can tell when the front ages out.
  • Each index enters and leaves the deque once, so the whole sweep is O(N).

    deque.pop_back()
  deque.push_back(i)

  • Use `>=` when evicting from the back so equal values don't pile up.

public int[] parkingIceCreamTruck(int[] A, int B) {
    Deque<Integer> deque = new LinkedList<>();

    int[] res = new int[N - B + 1];
    int indexToBeRemoved = 0;
    for (int i = 0; i < N; i++) {
        while (!deque.isEmpty() && A[i] >= A[deque.peekLast()]) {
            deque.removeLast();

        deque.offerLast(i);

    Deque<Integer> minDeque = new ArrayDeque<>();

            maxDeque.pollLast();

how to think about this topic
1. Identify the Tree Type

Is it a generic binary tree, BST, balanced tree, or complete tree? BST problems can exploit the left < node < right property to prune branches. Balanced trees have height O(log N). Complete trees can use array-based indexing (parent at i, children at 2i+1 and 2i+2).

2. Choose Traversal Strategy

DFS (recursion or stack) for problems requiring depth-first exploration: preorder for cloning, inorder for sorted order in BST, postorder for deletion. BFS (queue) for level-by-level problems: level-order traversal, right/left view, serialize/deserialize. DFS space = O(H), BFS space = O(W) where W is max width.

3. Define Recursive Subproblem

Most tree problems have elegant recursive structure. Ask: what do I need from left subtree? From right subtree? How do I combine them at this node? Define return type carefully (int for count/height, boolean for validation, TreeNode for construction). Base case is almost always null node.

4. Exploit BST Property

In BST problems, use the ordering to prune: if target < node, ignore right subtree. If target > node, ignore left subtree. This reduces search space from O(N) to O(H). For validation, pass min/max bounds down recursively. For range queries, prune branches outside range.

5. Handle Edge Cases Early

Check null root at the start. For BST, handle empty tree, single node, and duplicate values (clarify if allowed). For serialization, decide how to represent nulls (-1, 'N', etc). For deletion, cover 3 cases: leaf, one child, two children (use inorder predecessor/successor).

6. Track State Across Levels

For BFS, process nodes level-by-level using queue size snapshot. For views (left/right), track first/last node per level. For serialization, enqueue nulls to preserve structure. For parent-tracking problems, pass parent reference or use a map.

how to think
  • Counting nodes in `[B, C]` in a BST → DFS, but use the ordering to skip whole subtrees.
  • If `node.val < B`, the entire left subtree is too small — only go right (and vice versa).
  • When the node is inside the range, count it and explore both sides.
how to proceed — pseudocodetime O(N) · space O(H)
countRange(node, B, C):
  if node == null: return 0
  if node.val < B: return countRange(node.right, B, C)
  if node.val > C: return countRange(node.left, B, C)
  return 1 + countRange(node.left, B, C) + countRange(node.right, B, C)
Optimal O(N)
watch out
  • Null node returns 0.
  • Prune correctly: below B go right only, above C go left only — pruning the wrong side loses nodes.
  • Range is inclusive, so count nodes equal to B or C.
answer — optimal code (java)
public int countRangeInBST(TreeNode A, int B, int C) {
    return countRange(A, B, C);
}

private int countRange(TreeNode node, int B, int C) {
    if (node == null) {
        return 0;
    }

    if (node.val < B) {
        return countRange(node.right, B, C);
    }
    if (node.val > C) {
        return countRange(node.left, B, C);
    }

    return 1 + countRange(node.left, B, C) + countRange(node.right, B, C);
}
