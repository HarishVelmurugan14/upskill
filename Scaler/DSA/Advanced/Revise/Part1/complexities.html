Why Kadane's is O(N)

You make a single left-to-right pass, maintaining just two variables: the current running sum and the global maximum. At each element you decide whether to extend the current subarray or start fresh — a constant-time decision. No extra array is needed so space is O(1).

Why the optimized rain water is O(3N) space O(2N)

One pass builds a left-max array (N values), another builds a right-max array (N values) — that is 2N space. A third pass computes trapped water at each index. Total work: three full scans = O(3N) ≈ O(N).

Why in-place rotation is O(N×M) space O(1)

Transpose by swapping A[i][j] with A[j][i] — each cell is touched once. Then reverse each row — another O(N×M) pass. No auxiliary matrix is needed; every swap happens inside the original array.

Why in-place sign marking is O(3N)

Pass 1: replace all values outside [1,N] with N+1. Pass 2: negate A[A[i]−1] for every valid index. Pass 3: scan to find the first positive — that index+1 is the answer. Three sequential scans, no extra storage.

Why counting set bits is O(log N)

N has at most log₂(N) bits. Each iteration of N & (N−1) strips one set bit, so the loop runs at most as many times as there are set bits — bounded by log₂(N).

Why sumAfterBitwiseOR is O(27N)

For each of the N elements you process up to 27 bit positions (safe upper bound for 10^8 values). At each bit position you calculate how many subarrays have that bit set using the contribution formula — O(1) per bit. Total: 27 passes through N elements.

d13 — Recursion 1

Why recursion space is O(N)

Each recursive call occupies a stack frame. For a depth-N recursion (factorial, print 1..N) there are N frames alive simultaneously before any returns — that is O(N) stack space.

d14 — Recursion 2
MethodTimeSpace

Why Tower of Hanoi is O(2^N)

To move N disks you must move N−1 disks twice (once to the helper, once to the destination) plus one move for the largest disk. The recurrence T(N) = 2T(N−1) + 1 solves to 2^N − 1 moves.

Why binary exponentiation is O(log N)

Instead of multiplying A by itself N times, you square the result at each step. The exponent halves each iteration, so you need log₂(N) steps. The recursion stack is also log₂(N) deep.

Why the sliding window distinct approach is O(N)

Each element enters the window once and leaves once — two operations total per element. The frequency map update and distinct-count adjustment are O(1) per event. Total: O(2N) ≈ O(N), with at most K entries in the map at any time.

d18 — Sorting: Merge Sort
MethodTimeSpace
mergeSortO(N log N)O(N)
mergeContiguousSortedSubArraysO(high−low+1)O(high−low+1)
mergeTwoSortedArraysO(N+M)O(N+M)
Why merge sort is O(N log N)

The array is split in half log₂(N) times (depth of the recursion tree). At each level of the tree the total work to merge all sub-arrays is O(N) — every element is touched once across all merges at that level. Multiplying: log N levels × N work each = O(N log N). The temporary merge buffer is O(N) in the worst case.
