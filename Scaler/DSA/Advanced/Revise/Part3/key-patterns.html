Sieve of Eratosthenes — All Primes up to N d33 ▼
Signals in the question

You need all primes in a range, not just whether one number is prime. N can be up to 10^6 or more. Checking each number independently with a primality test would be too slow.

Standard solution skeleton

Create a boolean array isPrime[0..N], all true. Set isPrime[0] = isPrime[1] = false. For each p from 2 to √N: if isPrime[p] is still true, mark all multiples of p starting from p² as false. The indices still marked true at the end are all primes.

Two Pointers — Contiguous Subarray with Given Sum d35 ▼
Signals in the question

Find a contiguous subarray with a specific sum. The array contains only non-negative numbers (if negatives are possible, use prefix sum + HashMap instead). You need O(N).

Standard solution skeleton

Maintain a running window sum with two pointers, left and right. Expand right to increase the sum. When sum exceeds target, shrink from left. Stop when sum equals target or right reaches end.

Backtracking — Permutations, Subsets, Parentheses d36 ▼
Signals in the question

Generate all valid arrangements: "all permutations", "all subsets", "all combinations", "all valid bracket strings". You need to explore every possibility but prune invalid branches early. The output is a list of all results, not just a count.

Standard solution skeleton

Permutations: At each position, try every remaining element — swap it in, recurse, swap it back.

Subsets: At each element make a binary choice — include (add to current, recurse, remove) or exclude (recurse without adding). All 2^N leaves are valid.

Parentheses: Track open count and close count. Add '(' if open < n. Add ')' if close < open. When length == 2n, record the result.

The undo step (swap back, remove last element) is what makes it backtracking, not just recursion.

Slow/Fast Pointer — Linked List Middle & Cycle d39 ▼
Signals in the question

Find the middle of a linked list, detect a cycle, or find where a cycle starts — all without extra space. Two pointers moving at different speeds solve these in one pass.

Standard solution skeleton

Middle: slow moves +1, fast moves +2. When fast reaches the end, slow is at the middle.

Cycle detection: Same setup. If fast and slow meet, there is a cycle. If fast reaches null, no cycle.

Cycle start: After they meet inside the cycle, reset one pointer to head. Advance both by +1 each step. They meet exactly at the cycle's start node — a mathematical guarantee from the structure of cycles.

Merge Sort on Linked List d39 ▼
Signals in the question

Sort a linked list in O(N log N). You cannot use an auxiliary array. Random access is O(N) so quicksort with a good pivot is impractical. Merge sort is the natural fit because splitting and merging singly-linked lists is O(N).

Standard solution skeleton

Find the middle using slow/fast pointers. Disconnect the list at the middle. Recursively sort both halves. Merge the two sorted halves with a two-pointer merge (pick the smaller head node each time). Return the new head.

LRU Cache — HashMap + Doubly Linked List d39 ▼
Signals in the question

Design a cache with O(1) get and O(1) put, evicting the least recently used entry when capacity is exceeded. A plain HashMap gives O(1) lookup but not O(1) eviction order tracking.

Standard solution skeleton

Combine a HashMap (key → node) with a doubly linked list (most recent at front, LRU at tail). On get: look up in map, move the node to front, return value. On put: if key exists, update value and move to front; if new, add a node at front and add to map; if over capacity, remove the tail node and delete its map entry.
