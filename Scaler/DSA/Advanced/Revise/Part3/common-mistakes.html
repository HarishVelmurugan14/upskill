Common Mistakes
Part 3 · Days 33–40
Generic pitfalls by technique — not edge cases per problem.
Prime Numbers & Sieve
Sieve — starting multiples from p instead of p²
When crossing off multiples in the Sieve of Eratosthenes, start from p² (not 2p). All smaller multiples of p have already been marked by earlier primes. Starting at 2p means redundant work but not wrong results — yet it wastes time on large N.
isPrime — iterating past √N
If no divisor exists up to √N then N is prime. Any factor larger than √N would require a paired factor smaller than √N that you would have already found. Checking up to N is O(N); checking up to √N is O(√N).
Backtracking
Adding a reference instead of a copy to the result list
When adding a current state (ArrayList, char array) to the results, you must create a new copy: result.add(new ArrayList<>(currentList)). If you add the reference directly, all entries point to the same list — which ends up empty after backtracking unwinds.
Forgetting to undo the choice after recursion
Backtracking = make choice → recurse → undo choice. If you forget the undo step (e.g., not swapping back, not removing the last element added) the state is corrupted for sibling branches and subsequent results will include elements that should not be there.
Using wrong open/close counts for parentheses generation
You can add '(' only when open < n. You can add ')' only when close < open (never when close ≥ open — that makes an invalid string). Swapping these conditions produces malformed outputs with no syntax error.
Linked List Operations
Losing the rest of the list when reversing
When reversing a linked list, always save next = curr.next before you change curr.next = prev. Changing the pointer first severs the connection to the remainder of the list permanently.
Finding the wrong middle in slow/fast pointer
For palindrome-check: you want the start of the second half, not the end of the first. For merge sort: you want the node just before the midpoint so you can split cleanly. The exact stopping condition (fast != null && fast.next != null) matters for odd vs even length lists — test both.
Converting linked list to integer for digit-by-digit addition
Linked lists can represent numbers with hundreds of digits — converting to int or long will overflow. Always process digit by digit, carrying the overflow explicitly from one node to the next.
LRU Cache & Floyd's Cycle Detection
LRU — updating map but not moving the node in the list
When a cache key is accessed (get or put), you must move the corresponding node to the front of the doubly linked list, not just update the HashMap. Skipping the list update means the eviction order is wrong — the actual LRU node won't be at the tail.
Floyd's cycle start — resetting only one pointer, not both
After slow and fast meet inside the cycle, reset one pointer to head. Then advance both by one step at a time. They meet at the cycle start. A common error is advancing both at different speeds after the reset — that breaks the mathematical guarantee.
