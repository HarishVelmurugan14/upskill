d33 — Prime Numbers
ApproachTimeSpace
Sieve of EratosthenesO(N log log N)O(N)
isPrimeNumber checkO(√N)O(1)
Why Sieve is O(N log log N)

For each prime p you cross out N/p multiples. Summing N/p over all primes up to N gives N × (1/2 + 1/3 + 1/5 + 1/7 + …) which converges to N × log(log(N)) — a known result from number theory. In practice it is very close to O(N).

Why isPrime check is O(√N)

If N has a factor larger than √N, it must have a paired factor smaller than √N that you would have found earlier. So you only need to check divisors from 2 up to √N — that is at most √N iterations.

d35 — Two Pointers
ApproachTimeSpace
Brute force (nested loops)O(N²)O(1)
Two-pointer (subarray with given sum)O(N)O(1)
Why two pointers is O(N)

The left pointer only moves right and the right pointer only moves right. Together they make at most 2N steps across the whole traversal — each element is entered and exited at most once. No extra storage beyond two index variables.

d36 — Backtracking
MethodTimeSpace
generateParenthesisO(2^2N)O(N)
generateSubsets_yahnitO(2^N)O(N)
generatePermutationsO(N!)O(N)
Why subsets is O(2^N)

At each of N positions you make a binary choice: include or exclude the element. Two choices at each of N levels = 2^N leaf nodes in the recursion tree, and each leaf produces one subset. The stack depth is at most N.

Why permutations is O(N!)

For the first position you have N choices, for the second N−1, and so on down to 1. Total permutations = N × (N−1) × … × 1 = N!. Each permutation is a leaf in the recursion tree and takes O(N) to record.

Why parentheses generation is O(2^2N) — or more precisely O(Catalan(N))

At each position in a string of 2N characters you make a binary choice (open or close). Naively that is 2^(2N) branches, but validity constraints prune most — the true count is the N-th Catalan number which grows as O(4^N / N^1.5). O(2^2N) is the looser upper bound used in the source.

d39 — Linked List: Sorting & Problems
ApproachTimeSpace
Merge Sort on linked listO(N log N)O(log N)
Merge two sorted listsO(N+M)O(1)
Palindrome check (slow/fast + reverse)O(N)O(1)
Add two numbers digit by digitO(max(N,M))O(max(N,M))
Why merge sort on a linked list uses O(log N) space (not O(N))

Unlike array merge sort, there is no auxiliary array needed for merging — you relink existing nodes. The only stack space is the O(log N) recursion depth for splitting the list in half repeatedly.

d39 — Doubly Linked List & LRU
OperationTimeSpace
LRU Cache get/putO(1)O(capacity)
Floyd's cycle detection (meet)O(N)O(1)
Floyd's cycle start (after meet)O(N)O(1)
Why LRU is O(1) per operation

HashMap gives O(1) lookup by key. The doubly linked list allows O(1) node removal and insertion at the front (because every node stores both prev and next pointers — no traversal needed). Both structures together give O(1) for both get and put.
