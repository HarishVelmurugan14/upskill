Why heap insert/extract is O(log N)

A heap is a complete binary tree stored in an array. It has at most log₂(N) levels. Insert puts the new element at the bottom and sifts it up — at most log N swaps. Extract-min takes the top, puts the last element there, then sifts it down — also at most log N swaps.

Why build-heap is O(N) not O(N log N)

Naively inserting N elements one by one is O(N log N). But the bottom-up heapify approach starts from the last internal node and sifts down each node. Nodes near the bottom do very little work — the sum of all sift-down work telescopes to O(N). This is a classic result.

Why merge K sorted lists is O(N log K)

Total nodes across all lists = N. For each node you do one heap operation (extract the minimum head, push its successor). Each heap operation on K elements is O(log K). Total: N nodes × O(log K) per node = O(N log K).

Why minimum perfect squares is O(N √N)

The outer loop runs N times (one per target value). The inner loop tries every perfect square ≤ current value. The number of perfect squares up to N is √N. So the total work is N values × √N squares each = O(N √N).

Why Catalan number DP (numBSTrees) is O(A²)

To compute dp[n] you sum dp[0] × dp[n−1] through dp[n−1] × dp[0] — that is n multiplications. Do this for all values from 1 to A: total work = 1 + 2 + … + A = A×(A+1)/2 = O(A²). Source confirms: "#states × work per state = A × A iterations".

Why knapsack is O(N × W)

The DP table has N rows (items) and W+1 columns (capacities 0 to W). Each cell is filled in O(1) by looking up one or two previously computed cells. Total cells = N × (W+1) ≈ O(N × W). With a 1D rolling array the space drops to O(W).

Why DFS/BFS is O(V + E)

Each vertex is visited once — O(V). For each vertex you check all its edges — across all vertices that is O(E) total edge checks. Sum: O(V + E). The adjacency list itself takes O(V + E) space.

Why Dijkstra is O((V + E) log V)

Each vertex is extracted from the min heap at most once — O(V log V). Each edge may trigger a heap insert for a neighbor — O(E log V). Total: O((V + E) log V). The log V factor comes from heap operations on at most V elements.

Why Topological Sort is O(V + E)

Building in-degrees scans all edges — O(E). The BFS processes each vertex exactly once when its in-degree hits 0 — O(V). Decrementing neighbors scans edges again — O(E). No heap is needed, so no log factor. Total: O(V + E).
