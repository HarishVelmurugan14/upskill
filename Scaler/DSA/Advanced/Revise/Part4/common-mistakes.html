Common Mistakes
Part 4 · Days 44–56
Generic pitfalls by technique — not edge cases per problem.
Heaps
Min heap index formulas — getting parent/child wrong
In a 0-indexed array heap: left child = 2i+1, right child = 2i+2, parent = (i−1)/2. Using 1-indexed formulas (left = 2i, right = 2i+1) in a 0-indexed array shifts every node and silently corrupts the heap order.
Using a max heap when a min heap is needed (or vice versa)
Java's PriorityQueue is a min heap by default. For a max heap pass Collections.reverseOrder(). For the running-median problem you specifically need both: a max heap for the lower half and a min heap for the upper half. Mixing these up produces the wrong top element.
Not balancing the two heaps after each insert in running median
After each insertion the size difference between the lower-half max heap and the upper-half min heap must stay at most 1. If you skip the rebalancing step, the median read from the top of one heap will be wrong after every other insertion.
Brute-force TLE on delivery-time or scheduling problems
Sorting and repeatedly scanning for the minimum is O(N²). Always reach for a priority queue — inserting and extracting the minimum is O(log N), turning an O(N²) solution into O(N log N).
Dynamic Programming
Not identifying the state — what changes between subproblems
A DP state is the set of variables that completely describes a subproblem. For 1D DP the state is usually just the current index. For knapsack it is (index, remaining capacity). If you miss a state variable you will incorrectly reuse a stored answer for a different subproblem.
Storing all possibilities instead of just the minimum/maximum
For problems like "minimum perfect squares summing to N", there may be multiple equally valid ways at some values. The dp table should store only the optimal value at each position, not a list of paths. Storing multiple options inflates memory and makes the recurrence unclear.
0/1 Knapsack — iterating capacity forward in the bottom-up table
In 0/1 knapsack (each item used at most once), the inner loop over capacity must go from high to low when using a 1D table. Iterating low-to-high means you may pick the same item twice, effectively turning it into unbounded knapsack.
Forgetting to handle blocked cells in grid DP
When counting paths in a grid with obstacles, explicitly set dp[i][j] = 0 for any blocked cell before filling adjacent cells. If you let the recurrence run through a blocked cell it propagates phantom paths to downstream cells.
Graph — DFS
Returning immediately on finding the target — skipping other neighbors
In DFS for path-finding, do not return true the moment you reach the target inside a recursive neighbor loop — you must propagate the return value back and also skip processing remaining neighbors. The pattern is: if (dfs(neighbor)) return true;, not: dfs(neighbor); return true;.
Cycle detection — confusing visited with recursion stack
A node being "visited" (seen in any previous DFS call) is not the same as it being on the current recursion stack. A back edge to a visited-but-finished node is NOT a cycle in a directed graph. Only a back edge to a node still on the current stack means a cycle. Use a separate recStack[] array.
Building an adjacency list without null-safety
Always use adj.computeIfAbsent(from, k -> new ArrayList<>()).add(to) instead of manually checking if the key exists first. Missing the check means a NullPointerException when the first edge for a node is added.
Graph — BFS & Shortest Path
Not seeding all sources at once in multi-source BFS
In problems like rotten oranges, all rotten cells must be added to the queue before BFS begins. Adding them one at a time and running BFS after each will produce wrong distances — each source must spread simultaneously.
Dijkstra — updating distance without re-inserting into the heap
When a shorter path to a node is found, the updated distance must be pushed into the priority queue as a new (distance, node) pair. Java's PriorityQueue does not support decrease-key — you push duplicates and ignore stale entries when you pop. Forgetting to re-insert means the node's neighbors never get their relaxed distance propagated.
Topological sort — processing nodes with non-zero in-degree
Kahn's algorithm seeds the queue with all nodes whose in-degree is exactly 0. Adding any other nodes to the queue initially breaks the ordering guarantee. After processing a node, decrement its neighbors' in-degrees and enqueue only those that reach 0.
