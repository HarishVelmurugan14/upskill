Min Heap — Greedy Minimum Cost d44 ▼
Signals in the question

You must combine elements repeatedly and want the minimum total cost. The greedy insight is: always combine the two smallest available values, because combining larger values later accumulates more cost. A min heap gives you the two smallest in O(log N) each time.

Standard solution skeleton

Insert all initial values into a min heap. While more than one element remains: extract the two minimums, compute their sum (the cost for this step), add the sum back to the heap. Accumulate the total cost. Return total when one element remains.

Two Heaps — Running Median d45 ▼
Signals in the question

The median of a growing stream must be reported after each insertion. Sorting after every element is too slow. You need O(log N) per insertion and O(1) per median query.

Standard solution skeleton

Maintain a max heap for the lower half and a min heap for the upper half. On insert: if value ≤ max heap top, push to max heap; else push to min heap. Rebalance: if one heap has more than one extra element, move its top to the other heap. Median = top of the larger heap, or average of both tops if equal sizes.

Min Heap of Size K — Kth Largest / Nearly Sorted d46, d48 ▼
Signals in the question

Find the K-th largest in a stream or array. Or sort an array where each element is at most K positions away from its sorted position. The common thread: you only care about K elements at a time.

Standard solution skeleton

Kth largest: Maintain a min heap of size K. For each new element, if it is larger than the heap's top, pop the top and push the new element. After processing all elements, the heap's top is the Kth largest.

Nearly sorted (K-sorted): Push the first K+1 elements into a min heap. Then for each remaining element, pop the min (it is now in its correct position) and push the new element. Drain the heap at the end.

1D Dynamic Programming — Recurrence on a Single Dimension d49 ▼
Signals in the question

The problem can be broken into subproblems indexed by a single value (position, target sum, step count). The answer for index N depends on a constant number of smaller indices. Naive recursion re-solves the same subproblems exponentially — DP memoizes them.

Standard solution skeleton

Create a dp array of size N+1. Set the base case(s) (dp[0], dp[1]). Fill left to right: at each index express dp[i] in terms of previously computed values. Return dp[N]. If only the last two values are needed, replace the array with two variables to get O(1) space.

2D Dynamic Programming — Two Dimensions of State d50 ▼
Signals in the question

The state needs two changing parameters — for example (row, column) in a grid, or (number of digits, remaining sum). One dimension is not enough to uniquely describe the subproblem.

Standard solution skeleton

Create a 2D dp table. Identify what each cell dp[i][j] means. Fill in base cases (first row, first column, or boundary cells). Fill the rest using the recurrence. For grid paths: dp[i][j] = dp[i−1][j] + dp[i][j−1], set blocked cells to 0. Return dp[rows−1][cols−1].

Knapsack DP — Include or Exclude Each Item d51, d52 ▼
Signals in the question

Select items from a set given a weight/capacity constraint to maximize value or count ways. Each item either has one use (0/1 knapsack) or unlimited uses (unbounded). The total capacity is the second dimension of the state.

Standard solution skeleton

0/1 Knapsack: dp[i][w] = max(dp[i−1][w], value[i] + dp[i−1][w−weight[i]]) if w ≥ weight[i]. Each item row depends only on the previous row — iterate capacity high-to-low with a 1D array to avoid reuse.

Unbounded Knapsack: Same recurrence but dp[i][w] can use dp[i][w−weight[i]] (same row) since the item can be picked again. With a 1D array iterate capacity low-to-high.

Graph DFS — Traversal, Path Finding, Cycle Detection d53 ▼
Signals in the question

Explore all reachable nodes, find if a path exists between two nodes, or detect a cycle in a directed graph. DFS explores one branch as deep as possible before backtracking.

Standard solution skeleton

Mark the current node as visited and add it to the recursion stack (recStack[]). For each unvisited neighbor, recurse. After processing all neighbors, remove the current node from the recursion stack. For cycle detection: if a neighbor is in the recursion stack, a cycle exists. A neighbor that is visited but NOT in the recursion stack is not a cycle — it is a cross edge.

Multi-Source BFS — Spread from All Sources Simultaneously d54 ▼
Signals in the question

Multiple starting points all spread at the same rate (infection, rot, fire). You need the minimum time until everything is reachable. Running BFS from each source separately and taking the maximum is wrong — they spread in parallel, not sequentially.

Standard solution skeleton

Seed the queue with ALL source nodes before starting BFS, not one at a time. Run BFS level by level. Each level represents one time unit. Count levels until the queue is empty. Check whether all cells were reached — if not, return −1.

Dijkstra — Shortest Path in a Weighted Graph d55 ▼
Signals in the question

Find the shortest path in a weighted graph where all edge weights are non-negative. BFS finds shortest paths in unweighted graphs — Dijkstra generalizes this with a priority queue to handle weights.

Standard solution skeleton

Initialize dist[] = ∞ for all nodes, dist[source] = 0. Push (0, source) into a min heap. While the heap is not empty: pop the node with the smallest current distance. For each neighbor: if dist[node] + edge_weight < dist[neighbor], update dist[neighbor] and push (new dist, neighbor) into the heap. Ignore stale (old dist, node) entries when popped.

Topological Sort — Kahn's BFS with In-Degree d55 ▼
Signals in the question

Order tasks with dependencies (compile before link, take course A before course B). Or detect whether a directed graph has a cycle. If a valid ordering exists, the graph is a DAG.

Standard solution skeleton

Compute in-degree for every node. Add all nodes with in-degree 0 to the queue. While the queue is not empty: pop a node, add it to the result order, and for each neighbor decrement its in-degree. If a neighbor's in-degree reaches 0, add it to the queue. If the result order has fewer than V nodes at the end, a cycle exists.
