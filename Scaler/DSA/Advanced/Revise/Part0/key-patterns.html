Prefix Sum d03 ▼
Signals in the question

Multiple queries ask for the sum of a range [L, R] in an array. Computing each sum from scratch is too slow. The array doesn't change between queries (static array).

Standard solution skeleton

Allocate a prefix array of size N. Set prefix[0] = A[0]. For each i from 1 to N−1 set prefix[i] = prefix[i−1] + A[i]. To answer sum(L, R): return prefix[R] − prefix[L−1] (handle L=0 as a special case returning prefix[R]). For even/odd prefix sums, build two separate prefix arrays — one for even-indexed elements and one for odd-indexed.

Carry Forward d04 ▼
Signals in the question

You need a count or aggregate that depends on what came before the current element. You only need to scan in one direction. The answer for each position can be derived from a single running value maintained from previous positions.

Standard solution skeleton

Initialize a carry variable to 0 before the loop. Scan left to right (or right to left depending on direction needed). At each element, either update the carry (when you see an 'A') or use the carry to contribute to the answer (when you see a 'G'). No second pass needed.

Contribution Technique d04/d05 ▼
Signals in the question

The question asks for the sum of something across all subarrays. Enumerating every subarray is O(N²) or O(N³) and too slow. Each element's contribution to the total can be expressed as a formula based on its position.

Standard solution skeleton

For sum of all subarray sums: iterate once. At index i (0-based), A[i] contributes A[i] × (i+1) × (N−i) to the total. Sum this for all i. For other contribution problems, identify what property of position drives how many times an element appears in the answer.

Sliding Window d05 ▼
Signals in the question

You have a fixed window size K and need to compute something (max sum, average, condition) for every window position. Recomputing from scratch for each position would be O(N×K).

Standard solution skeleton

Compute the sum of the first K elements as the initial window. Then for each new position i from K to N−1: add A[i] (the incoming element) and subtract A[i−K] (the outgoing element). The window sum is always current. Apply your condition or track maximum/minimum as you go.

Memory Management d07 ▼
Signals in the question

Not a problem-solving pattern — a Java behavior pattern. Applies whenever you pass arrays or objects to methods and expect changes to propagate back to the caller.

Standard solution skeleton

Primitives (int, double) are copied — changes inside the method do not affect the caller. Return the new value to propagate it. Arrays and objects pass the reference — mutations to existing elements (a[0] = x) are visible to the caller. But re-initializing the reference (a = new int[]{...}) inside the method creates a new heap object — the caller's reference is unaffected. To propagate a new array, return it.
