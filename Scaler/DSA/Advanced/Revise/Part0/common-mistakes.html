Common Mistakes
Part 0 · Days 3–7
Generic pitfalls by technique — not edge cases per problem.
Prefix Sum
Recomputing the range sum instead of using the prefix array
Once the prefix array is built, a range sum [L, R] is prefix[R] − prefix[L−1]. Recomputing from scratch each query turns O(1) into O(N) and defeats the purpose entirely.
Off-by-one on the left boundary
prefix[R] − prefix[L−1] is correct. Writing prefix[R] − prefix[L] skips the element at index L. Always subtract prefix[L−1], not prefix[L].
Forgetting that element removal shifts parity of all indices to the right
When you remove index i, every element at position > i moves left by one — its even/odd index flips. You cannot treat the two halves independently; the parity of the right half is the opposite of what it was.
Carry Forward
Scanning the wrong direction
Carry forward works by accumulating a value as you scan in one direction. Scanning right-to-left when you need left-to-right (or vice versa) gives wrong counts. Lock down direction before coding.
Counting the element itself when it shouldn't contribute
When counting AG pairs, at each 'G' you add the count of 'A's seen so far — meaning A must strictly come before G. If you increment the counter before checking the current element, you'll count positions where A and G are the same index.
Contribution Technique
Confusing the number of subarrays an element belongs to
Element A[i] (0-indexed) is the left boundary of (i+1) subarrays and the right boundary of (N−i) subarrays. Its total contribution is A[i] × (i+1) × (N−i). Mixing up (i+1) with i, or (N−i) with (N−i−1), silently miscounts every element.
Sliding Window
Re-summing the window from scratch on each slide
Brute force recomputes the sum of K elements per step: O(N×K). The sliding window adds one element and removes one element: O(N). For large K the difference is enormous — the window exists specifically to avoid the re-sum.
Not removing the outgoing element before adding the incoming one
Order matters: when sliding from position i to i+1, remove A[i−K+1] (the element leaving) and add A[i+1] (the element entering). Doing it in the wrong order, or forgetting to remove, corrupts the running sum.
Memory (d07)
Expecting primitive changes inside a method to affect the caller
Java passes primitives by value — a copy is made. Any change to the local copy is invisible to the caller. To propagate a change, return the new value.
Re-initializing an array inside a method and expecting the caller to see it
Writing a = new int[]{...} inside a method creates a new heap object and points the local reference there. The caller's reference still points to the original. Only mutations to the existing array (a[0] = x) are visible to the caller.
