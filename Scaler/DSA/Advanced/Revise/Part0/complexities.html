d03 — Prefix Sum
MethodTimeSpace
bruteForceO(n×q)O(1)
optimalO(n)O(n+q)
Why O(n×q) vs O(n)

Brute force recomputes the sum for each of q queries by scanning the array each time — q queries × n elements = O(n×q). The optimal approach builds a prefix array once in O(n), then answers each query in O(1) with a subtraction — total O(n + q). For large q the difference is dramatic.

d04 — Carry Forward
MethodTimeSpace
bruteForce (AG pairs)O(N²)O(1)
optimal (AG pairs)O(n)O(1)
numberOfAGPairsInAStringO(n)O(1)
Why O(N²) vs O(N)

Brute force checks every pair (i, j) with i < j to see if A[i]='A' and A[j]='G' — that is N×(N−1)/2 pairs. Carry forward scans once: at each 'G', the number of valid pairs ending here equals the number of 'A's seen so far, which is tracked in a single counter. One pass = O(N).

d04 — SubArrays
MethodTimeSpace
bruteForce (smallest subarray with min+max)O(N³)O(1)
optimal (smallest subarray with min+max)O(N)O(1)
storeAllSubArraysInA2DMatrixO(N³)O(1)

Why O(N³) for brute force subarrays

To enumerate all subarrays you have O(N²) start/end pairs. For each pair you might scan the contents (O(N)), giving O(N³). The carry-forward approach for min/max tracking lets you maintain running min and max as you expand right — one pass right-to-left = O(N).

MethodTimeSpace

Why O(N) for contribution formula

Instead of computing every subarray's sum, observe that A[i] appears in exactly (i+1)×(N−i) subarrays (i+1 choices for the left boundary, N−i choices for the right boundary). Multiply A[i] by this count and sum for all i — one loop, O(N). The O(N²) approaches still enumerate pairs of boundaries.

SlidingWindowTechnique_5
MethodTimeSpace
approach1 (brute)O(N²)O(1)
optimal (sliding window)O(N)O(1)
Why O(N) for sliding window

The brute force recomputes the sum of K elements for each of the N−K+1 windows: O(N×K). The sliding window maintains a running sum — each new window is computed by adding one element and removing one element, both O(1). Across N windows that is O(N) total.
